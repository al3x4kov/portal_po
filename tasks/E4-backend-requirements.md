# Эпик E4 — Бэкенд: требования и связи (apps/server)

Ценность: CRUD требований в `.md`, проверка уникальности, типизированные связи с
проверками целостности, безопасное удаление. Трассировка: FR-6, FR-7, FR-8, FR-9.

---

## T-401 · Репозиторий требований (CRUD .md) · [M] · параллельно: да
- **Что:** `FsRequirementRepo`: чтение всех `.md` проекта, запись/обновление/удаление
  одного требования через core-сериализацию и atomicWrite.
- **Где:** `apps/server/src/repositories/FsRequirementRepo.ts`.
- **Критерии приёмки:**
  - [ ] Загрузка проекта собирает список требований; «битые» файлы помечаются, не роняют.
  - [ ] Запись атомарна; файл называется `requirements/<id>.md`.
- **Тесты (Vitest, temp dir):** CRUD, битый файл, round-trip с диска.
- **Зависимости:** blocked by: T-202, T-302 · blocks: T-402, T-404, T-405.
- **Трассировка:** §2.5, FR-6.4.

## T-402 · Сервис требований: create/update · [M] · параллельно: да
- **Что:** `RequirementService.create/update` с проверкой уникальности (T-204), условных
  полей (T-203), генерацией id и `createdAt/updatedAt`.
- **Где:** `apps/server/src/services/RequirementService.ts`.
- **Критерии приёмки:**
  - [ ] Дубль имени → `409`; невалидные поля → `422`.
  - [ ] При «не реализовано» без квартала/года — ошибка.
  - [ ] Обновление сохраняет id и историю меток времени.
- **Тесты (Vitest):** создание, дубль, условные поля, обновление.
- **Зависимости:** blocked by: T-203, T-204, T-401 · blocks: T-403.
- **Трассировка:** FR-6, §2.4.1.

## T-403 · API требований + проверка имени · [S] · параллельно: да
- **Что:** `GET/POST /requirements`, `PUT/DELETE /requirements/:rid`,
  `GET /requirements/check-name` (для real-time проверки на фронте).
- **Где:** `apps/server/src/routes/requirements.ts`.
- **Критерии приёмки:**
  - [ ] `check-name` возвращает `{available:boolean}` с учётом типа и исключения своего id.
  - [ ] CRUD-эндпоинты валидируются и возвращают корректные коды.
- **Тесты (Vitest/integration):** check-name (свободно/занято), CRUD.
- **Зависимости:** blocked by: T-402 · blocks: T-406, T-604, T-605.
- **Трассировка:** FR-6.6, FR-7.

## T-404 · Сервис и API связей · [M] · параллельно: да
- **Что:** `LinkService` + `POST/DELETE /api/projects/:id/links`: создание/удаление связи
  как взаимно-обратной пары с проверками целостности (T-205).
- **Где:** `apps/server/src/services/LinkService.ts`, `routes/links.ts`.
- **Критерии приёмки:**
  - [ ] Связь пишется в оба `.md`; удаление снимает обе стороны.
  - [ ] Цикл / второй родитель / self-link / разные типы → `409`/`422` с пояснением.
- **Тесты (Vitest):** валидная связь, каждая ошибка целостности, удаление пары.
- **Зависимости:** blocked by: T-205, T-401 · blocks: T-406, T-606.
- **Трассировка:** FR-8, §2.4.3–2.4.6.

## T-405 · Удаление требования с каскадом ссылок · [S] · параллельно: да
- **Что:** `DELETE /requirements/:rid`: удалить файл + снять все обратные ссылки (T-206);
  политика для узла с потомками (FR-9.3).
- **Где:** `apps/server/src/services/RequirementService.ts` (delete), `routes`.
- **Критерии приёмки:**
  - [ ] После удаления нет висячих ссылок (проверка целостности проекта).
  - [ ] Удаление узла с потомками блокируется с понятной ошибкой.
- **Тесты (Vitest):** каскад, узел с потомками, лист.
- **Зависимости:** blocked by: T-206, T-401 · blocks: T-406, T-606.
- **Трассировка:** FR-9, §2.4.7.
