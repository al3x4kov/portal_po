# Эпик E2 — Доменное ядро (packages/core)

Ценность: чистая, оттестированная бизнес-логика (модели, MD-формат, валидации,
граф связей) без зависимости от ФС/HTTP. Трассировка: разделы 2.4, 2.5 ТЗ; NFR-2, NFR-8.
Все задачи эпика параллелятся после T-201.

---

## T-201 · Доменные типы и Zod-схемы · [M] · параллельно: нет (база эпика)
- **Что:** типы `Requirement`, `Link`, enums (`RequirementType`, `Criticality`,
  `LinkType`) и Zod-схемы валидации (раздел 5.1 arch.md).
- **Где:** `packages/core/src/domain/`, `packages/core/src/validation/schema.ts`.
- **Критерии приёмки:**
  - [ ] Схемы валидируют корректные объекты и отклоняют некорректные.
  - [ ] Генерация ULID для `id` инкапсулирована (`newId()`).
- **Тесты (Vitest):** валидные/невалидные объекты, генерация уникальных id.
- **Зависимости:** blocked by: T-101 · blocks: T-202…T-206.
- **Трассировка:** §2.2.

## T-202 · Сериализация/парсинг MD (round-trip) · [M] · параллельно: да
- **Что:** `serialize(req): string` и `parse(md): Requirement` через gray-matter+js-yaml.
- **Где:** `packages/core/src/md/`.
- **Критерии приёмки:**
  - [ ] Round-trip: `parse(serialize(r))` эквивалентен `r`.
  - [ ] Битый frontmatter → `ParseError` (не исключение рантайма), с понятным message.
  - [ ] Описание (body) сохраняется как Markdown без искажений.
- **Тесты (Vitest):** round-trip на наборе требований; битые входы; пустое описание.
- **Зависимости:** blocked by: T-201 · blocks: T-401, T-502.
- **Трассировка:** §2.5, NFR-2.

## T-203 · Валидация полей и ограничений · [S] · параллельно: да
- **Что:** правила: `targetQuarter`/`targetYear` обязательны при `implemented=false`;
  длины name (1–200), description (≤5000); год 2020–2100.
- **Где:** `packages/core/src/validation/rules.ts`.
- **Критерии приёмки:**
  - [ ] Незаполненные квартал/год при «не реализовано» → ошибка.
  - [ ] При `implemented=true` квартал/год игнорируются/очищаются.
  - [ ] Нарушения длин/диапазонов отклоняются.
- **Тесты (Vitest):** таблица кейсов по каждому правилу.
- **Зависимости:** blocked by: T-201 · blocks: T-402.
- **Трассировка:** §2.2, §2.4.

## T-204 · Проверка уникальности имени · [S] · параллельно: да
- **Что:** `assertUniqueName(reqs, candidate)` — уникум по (type), регистронезависимо, trim.
- **Где:** `packages/core/src/graph/uniqueness.ts`.
- **Критерии приёмки:**
  - [ ] Дубль с другим регистром/пробелами распознаётся как конфликт.
  - [ ] Переименование самого себя в то же имя — разрешено (исключить свой id).
- **Тесты (Vitest):** дубли, регистр, пробелы, self-rename.
- **Зависимости:** blocked by: T-201 · blocks: T-402, T-403.
- **Трассировка:** §2.4.1.

## T-205 · Графовые проверки связей · [M] · параллельно: да
- **Что:** `assertNoCycle`, `assertSingleParent`, `assertNoSelfLink`, `assertSameType`
  для иерархических/зависимостных связей.
- **Где:** `packages/core/src/graph/integrity.ts`.
- **Критерии приёмки:**
  - [ ] Цикл `A→B→…→A` отклоняется с указанием пути.
  - [ ] Второй `CHILD_OF` (второй родитель) отклоняется.
  - [ ] Self-link и связь разных типов (FUNCTION↔NFR) отклоняются.
  - [ ] Связь создаётся как взаимно-обратная пара (PARENT_OF↔CHILD_OF).
- **Тесты (Vitest):** все нарушения + валидные связи; построение пары.
- **Зависимости:** blocked by: T-201 · blocks: T-404.
- **Трассировка:** §2.3, §2.4.3–2.4.6.

## T-206 · Каскадная чистка ссылок при удалении · [S] · параллельно: да
- **Что:** `cascadeUnlink(reqs, deletedId)` — удалить все обратные ссылки на удаляемое;
  политика для узла с потомками (по умолчанию запрет, см. FR-9.3).
- **Где:** `packages/core/src/graph/cascade.ts`.
- **Критерии приёмки:**
  - [ ] После удаления нет «висячих» ссылок ни в одном требовании.
  - [ ] Удаление узла с потомками возвращает ошибку/флаг (политика запрета).
- **Тесты (Vitest):** чистка ссылок, узел с потомками, узел-лист.
- **Зависимости:** blocked by: T-201, T-205 · blocks: T-405.
- **Трассировка:** §2.4.7, FR-9.3.
