## Дизайн-токены
Единый источник — `tokens.css` (CSS-переменные, light + dark).
- Primary: indigo `#4f46e5`; Accent: sky `#0ea5e9`.
- Нейтральные: slate-шкала; семантические success/warning/danger/info.
- Критичность: Low→зелёный, Medium→янтарь, High→оранжевый, Critical→красный.
- Типографика: системный sans + mono для путей/ID. Радиусы 6/10/16, тени sm/md/lg.
При переносе в код: токены кладутся в `tailwind.config` (см. `arch.md`).

## Состояния, заложенные в макеты
- Валидация имени: «свободно» / «занято» (new-project), «уникально» / «дубликат» (requirement-modal).
- Условные поля «Квартал/Год» показываются только при «Не реализовано».
- Ошибка целостности связи (цикл / второй родитель) в link-modal.
- Удаление: подсказка о наличии/отсутствии потомков.

## Решения UX
- Деструктив (удаление, отмена) — через подтверждение.
- Дерево: отступом слева показывается вложенность; раскрытие ▾/•.
- Действия строки (Связать/Удалить) появляются по наведению, на мобильном — всегда видны.
- Тёмная тема — переключатель в шапке (класс `dark` на `<html>`).

### Единый слой видимости строк (A6#4) — ключевое решение
Поиск (B3), сворачивание дерева (B1) и фильтр критичности (B5) **не** являются
независимыми механизмами. Все три вычисляют один набор `visibleRows`:
- Строка видна, если она **сама** прошла активные условия (совпала с поиском / прошла
  фильтр критичности / не свёрнута), **или** является **предком** видимого потомка.
- Предок, попавший в набор только «за компанию», рендерится как **контекст**: приглушён
  (`opacity .6`) и помечен меткой «предок». Так не бывает «сирот» (потомок без родителя) —
  дерево всегда остаётся связным (тест-ситуация S28).
- Пустой набор → явный empty-state (S29), а не пустая таблица.

### B2 — раскладка таблицы (решение)
- **Ширина.** Контент растянут до `max-width:1600px` во всю ширину монитора (было
  `max-w-6xl`/1152px — на широких экранах пустота справа). Таблица — `width:100%`.
- **Плотность.** Компактнее вертикальный ритм (`padding:9px 16px`), sticky-заголовок таблицы
  и sticky-тулбар под шапкой.
- **Колонки.** Порядок: `Требование` (гибкая, ~34%) · `Критичность` (фикс. 130px) ·
  `Реализация` (фикс. 140px) · `Описание` (забирает остаток ширины) · действия. Узкие
  метаданные зафиксированы, длинный текст получает максимум места.
- **Тулбар.** Единая панель управления видимостью: переключатель вида + поиск + фильтр
  критичности + счётчик «Показано N из M». Это же место — точка входа во все механизмы A6#4.

### B4 — описание: выбрана **боковая панель (drawer)** (закрывает FR-7.4)
Рассмотрены три варианта: раскрытие строки, поповер, боковая панель.
- Раскрытие строки ломает вертикальный ритм плотной таблицы и «прыгает» при длинном тексте.
- Поповер тесен для 5000 символов Markdown и обрезается у краёв экрана.
- **Боковая панель справа** даёт комфортную ширину чтения, прокрутку, сохраняет таблицу на
  виду (контекст не теряется) и вмещает мета-шапку (тип, критичность, срок, путь) и действия
  «Редактировать/Удалить». Это современный паттерн (Linear/Notion/Height). В таблице описание —
  одна усечённая строка (`…`), клик по ячейке открывает панель. **Решение принято: drawer.**

### B6 — модалка (решение)
Композиция сгруппирована по смыслу с разделителями: (1) идентификация — Название +
инлайн-проверка уникальности; (2) классификация — Критичность сегментами с цветными точками
вместо `select`; (3) статус реализации сегментами, условный блок «Квартал/Год» появляется
только при «Не реализовано»; (4) Описание с счётчиком символов `N / 5000`. Первичное действие
переименовано в «Сохранить».

`.btn`/`.badge`/`.input`/`.card`, таблица `tw`, мультиселект-дропдаун и модалка из v2.

| Файл | Задача | Что решает |
|------|--------|-----------|
| `screens/main-v3-impl-filter.html` | T1 | Мультиселект-фильтр по колонке «Реализация» в тулбаре |
| `screens/main-v3-links.html` | T2 | Блок «Связи» в карточке требования + пустое состояние |
| `screens/main-v3-link-delete.html` | T3 | Удаление связи с инлайн-подтверждением |
| `screens/main-v3-nfr-from-ft.html` | T4 | «+ НФТ» из строки ФТ с предустановленной связью `BLOCKED_BY` |
| `screens/main-v3-excel.html` | T5 | Эталон вида экспортного листа `.xlsx` «как в UI» |

### T1 — фильтр «Реализация» (решение)
- Отдельная кнопка-мультиселект в тулбаре **рядом** с «Критичность», тот же паттерн дропдауна
  (чекбоксы + «Сбросить»/«Применить» + счётчик-бейдж). Значения: «Реализовано» / «Не реализовано».
- Работает через **единый слой видимости** (A6#4, `computeVisibleRows`): показываются совпадения
  и их **предки-контекст** (приглушены, метка «предок»), пересекается с поиском и критичностью
  без «сирот». Сброс возвращает всё; пустой результат → явный empty-state.

### T2 — блок «Связи» (решение)
- В модалке ФТ/НФТ, отдельным блоком после идентификации: заголовок «Связи (N)» + кнопка
  «Добавить связь» (ведёт в `link-modal`). Каждая связь — строка с иконкой типа, **человекочитаемой
  формулировкой** (`блокируется «…»`, `связана с «…»`, `является дочерней для «…»`) и мелким
  тех-типом (`BLOCKED_BY · НФТ`). Формулировки едины с экспортом (T5) и модалкой связывания.
- **Пустое состояние** — dashed-карточка «Связей нет» с подсказкой. Данные из `requirement.links` + карта slug→имя.

### T3 — удаление связи (решение)
- Кнопка-корзина у каждой связи (появляется по ховеру, на мобильном всегда). Клик → строка
  переходит в **инлайн-подтверждение** (без полноэкранной модалки, чтобы не терять контекст
  остальных связей): текст «Удалить связь «…»?» + «Отменить»/«Удалить» (danger). Консистентно с
  удалением требования (`main-delete`). Удаляет реципрокную пару (`useDeleteLink`).

### T4 — «+ НФТ» из строки ФТ (решение)
- Компактное действие «+ НФТ» в ряду действий строки ФТ (рядом со «Связать»/«Удалить»). Открывает
  модалку создания НФТ с **плашкой** предустановленной связи: «Будет связано: «Оплата картой»
  *блокируется* этим НФТ (BLOCKED_BY)». Направление (обсуждено с Архитектором): источник ФТ,
  тип `BLOCKED_BY`, цель — новое НФТ; реципрокная `DEPENDS_ON` на стороне НФТ. Первичное действие —
  «Создать и связать»; связь создаётся автоматически после сохранения.

### T5 — экспорт Excel «как в UI» (решение)
- Макет-эталон (не настоящий xlsx) для backend-разработчика. **Один содержательный лист**
  «Требования» вместо прежних двух «сырых» (Requirements + Links). Колонки повторяют портал:
  Требование (отступ 20px/уровень = indent-level ячейки), Тип (ФТ/НФТ), Критичность (текст +
  цветная точка как условное форматирование), Реализация («Реализовано»/«Q3 2026»), Описание,
  Связи (словами). Порядок строк — как в дереве: ФТ с иерархией, затем НФТ. Оформление имитирует
  Excel (буквы колонок, номера строк, вкладка листа) — чтобы задать целевой вид.
