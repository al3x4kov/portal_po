## 2026-07-04 — AI подгрузка ФТ/НФТ из документации

### Автоматизация
- На главном экране проекта, в футере справа от «+ Функция»/«+ НФТ», новая кнопка
  **«AI подгрузка из документации»**. Модальное окно: загрузка архива документации
  (zip / tar.gz, до 50 МБ, внутри .md/.markdown/.txt), выбор модели (по умолчанию — модель
  проекта; без API-ключа — серый селект с подсказкой, как настроить), кнопка
  «Запустить анализ» (активна после выбора файла).
- Серверный конвейер по правилам скилла `project-po-extract`: распаковка во временную
  директорию (с защитой от zip-slip) → **последовательные** вызовы AI Hub по чанкам ≤12k
  символов (расчёт на маленькое контекстное окно, напр. Qwen-Coder-Next) → агрегация с
  дедупликацией → наполнение проекта. Извлечение строго из текста документации, без
  домысливания; каждое требование обязано иметь провенанс — он записывается в поле
  **«Источник»** требования.
- **Существующие ФТ/НФТ не перезаписываются**: совпадение имени в рамках типа — пропуск
  (идемпотентность: повторный запуск того же архива ничего не дублирует).
- Пробелы источника заполняются умолчаниями (критичность MEDIUM; не реализовано + target
  следующий квартал) с warn в логе.
- В модалке при выполнении: прогресс-бар с процентами, живой лог (info/warn/error),
  кнопка «Остановить». X/клик-вне при запущенной автоматизации — предупреждение
  «Прекратить автоматизацию?»; в покое — закрытие сразу. Успех — итоги (создано ФТ/НФТ,
  связей, пропущено существующих) и кнопка «Закрыть и перейти к проекту». Ошибка любого
  этапа — сообщение + инструкция «Что делать» и «Повторить анализ».

## 2026-07-04 — Плавающий виджет AI-чата на всех экранах

### Виджет чата
- На всех экранах приложения (стартовый, создание/импорт/открытие проекта, дерево требований,
  дашборд, AI) доступен плавающий AI-чат. По умолчанию — небольшая круглая иконка сообщения
  (FAB) в правом нижнем углу; её можно перетаскивать по экрану мышью.
- Клик по иконке открывает виджет чата (иконка скрывается); виджет тоже перетаскивается —
  за верхнюю панель.
- Верхняя панель виджета: выпадающий список **переопределения модели** (по умолчанию — модель
  текущего проекта из настроек AI; выбор в списке действует только для чата и в конфиг проекта
  не пишется), кнопка **«Новый чат»** (затирает переписку) и **«X»** (сворачивает виджет обратно
  в иконку, переписка сохраняется и доступна при повторном открытии).
- Если AI Hub не настроен (нет API-ключа из меню AI, см. релиз ниже) — список моделей серый и
  неактивный, по наведению подсказка как настроить; отправка сообщений отключена.
- Середина виджета — лента переписки (вмещает 5–6 сообщений, ≥500 символов без прокрутки):
  пузыри с иконками **бота** (слева) и **пользователя** (справа), автопрокрутка к последнему,
  индикатор «печатает…», читабельные сообщения об ошибках (история при ошибке не теряется).
- Низ — поле ввода (Enter — отправить, Shift+Enter — перенос строки) и кнопка «Отправить».
- Переписка живёт в памяти вкладки: переживает навигацию между экранами, очищается кнопкой
  «Новый чат» или перезагрузкой страницы; на диск/сервер не сохраняется.

### API
- `POST /api/ai/chat` — единый контракт в `@po/core` (`aiChatRequestSchema`/`aiChatResponseSchema`):
  `{ projectId?, model?, messages[] }` → `{ message: { role: 'assistant', content } }`.
  Модель: override из запроса → модель проекта → иначе 400. В запрос уходят последние

  наружу не отдаётся; ошибки апстрима → 502 с санитизацией ключа.

## 2026-07-04 — Интеграция с AI Hub

### Экран «AI» (пункт меню слева)
- Новый пункт меню «AI» (иконка-искра) в боковой панели — виден для любого открытого проекта,
  ведёт на экран `/p/:id/ai`.
- Экран из 2 частей: слева — подключение к AI Hub (API-ключ, Base URL, выбор модели из списка),
  справа — пошаговая инструкция по подключению (авторизация → API-ключ → Base URL → список
  моделей → первый запрос) со ссылкой на hub.ai.sbt и примером кода.
- **Хранение настроек (гибрид):** API-ключ и Base URL — глобально (персональный набор на
  пользователя); выбранная модель — per-project. Ключ хранится в локальном `.ai-config.json`
  (в `.gitignore`), в UI маскируется, наружу (в API) в открытом виде не отдаётся и не логируется.
- Список моделей подтягивается из AI Hub; при недоступности — ручной ввод model id.

### Генерация описания требования (AI Hub generation)
- В форме создания/редактирования требования у поля «Описание» — кнопка «AI Hub generation»:
  запрос в AI Hub → **превью** → «Отменить» / «Применить». «Применить» добавляет описание в конец
  текущего с новой строки (не затирая введённое). Без настроенного ключа/модели кнопка неактивна
  и ведёт на экран «AI».
- В запрос передаётся контекст требования (имя, тип, критичность, текущее описание, имя проекта) +
  опциональная подсказка пользователя. Промпт спроектирован по best practices инженерии требований:
  явные критерии качества (недвусмысленность, понятность, корректность, проверяемость), стиль
  портала, few-shot, запрет на выдумывание фактов сверх контекста; вывод на русском.

### API (AI Hub, OpenAI-совместимый)
- `GET /api/ai/config` (ключ не отдаётся — только `hasApiKey`), `PUT /api/ai/config`,
  `GET /api/ai/models`, `POST /api/ai/generate-description`.
- Клиент — обёртка над `openai` SDK; `baseURL` берётся из конфига. Зависимость `openai` добавлена
  на сервер.

### Безопасность
- API-ключ наружу не отдаётся и не логируется; ошибки апстрима санитизируются (ключ вырезается).
  `baseURL` валидируется как URL. Приложение локальное однопользовательское — SSRF-риск от
  пользовательского `baseURL` (свой же хост) принимается осознанно.

### Подключение за корпоративным CA / прокси (исправление)
AI Hub (`api.ai.sbt`) часто закрыт внутренним корпоративным CA, которому доверяет ОС/`curl`, но
не Node (его `fetch`/undici) — из-за чего сохранение/загрузка моделей падали с 502 «Connection
error.». Настройка TLS/прокси вынесена в env и применяется **только** к клиенту AI Hub (не
глобально), к обеим операциям — списку моделей и генерации описания:
- **По умолчанию проверка TLS для AI Hub отключена** (scoped только на AI Hub, не глобально) —
  чтобы работало «из коробки» за внутренним CA. Это осознанный временный дефолт; ужесточить —
  задать `AI_HUB_INSECURE_TLS=0` или указать `AI_HUB_CA_CERT`.
- `AI_HUB_CA_CERT=/путь/к/ca.pem` — доверять корпоративному корневому CA (безопасный вариант;
  автоматически включает проверку). Эквивалент штатного `NODE_EXTRA_CA_CERTS` тоже работает.
- `AI_HUB_INSECURE_TLS=0` — принудительно ВКЛЮЧИТЬ проверку TLS для AI Hub.
- `AI_HUB_PROXY` / `HTTPS_PROXY` — ходить в AI Hub через HTTP(S)-прокси (Node `fetch` не читает
  прокси-переменные сам).
Плюс сообщение об ошибке 502 теперь показывает всю цепочку причин (напр.
`… ← unable to verify the first certificate (UNABLE_TO_VERIFY_LEAF_SIGNATURE)`) с вырезанным ключом.

## 2026-07-03 — Экспорт: группировка фильтров + выбор данных для выгрузки

### Экраны выбора требований (экспорт и TaskTracker)
- Фильтры на экранах «Выбор требований для экспорта» и «Выбор ФТ/НФТ для TaskTracker» (общий
  компонент `RequirementPickerModal`) разбиты на **именованные группы**: «Критичность»,
  «Реализация», «Источник», и отдельная группа «Выбор» («Выбрать все / Снять выделение» + счётчик).
- Фильтр по «Источник» теперь **кейс-инсенситивный**: значения, отличающиеся только регистром
  (напр. «АС21» и «ас21»), считаются одним значением и группируются в один чип.

### Экран «Формат выгрузки» — выбор данных для выгрузки
- Добавлен блок «Данные для выгрузки» из двух групп чекбоксов:
  - **Обязательные данные** (всегда включены, снять нельзя): Название, Критичность, Статус реализации.
  - **Дополнительные данные** (переключаемые, по умолчанию все включены): Источник требования,
    Описание, Справочная информация, Связи.
- Выбор данных влияет на **содержание всех трёх форматов** (Excel `.xlsx`, `.zip`, `.tar.gz`):
  - **Excel**: динамический набор колонок. По умолчанию 8 колонок
    (Требование · Тип · Критичность · Реализация · Источник · Описание · Справочная информация · Связи);
    ранее было 6 (без Источника и Справочной информации). Справочная информация выводится многострочно
    «тип: значение»; заливка критичности и отступ по дереву сохранены.
  - **OpenSpec-архивы (`.zip`/`.tar.gz`)**: `.md` требования содержит только выбранные секции
    (`- source`, тело описания + `#### Scenario`, `#### Info`, `#### Links`). Обязательные поля и
    техническое `createdAt`/`updatedAt` присутствуют всегда; пустые опциональные секции не выводятся.
- **Превью-подсказка**: по текущему выбору показывает, какие колонки Excel и секции OpenSpec попадут
  в выгрузку.
- **Обратная совместимость / round-trip**: при выбранных всех полях выгрузка байт-в-байт совпадает с
  прежней (лосслесс). Отфильтрованный архив — «выгрузка для чтения»: он валидно импортируется, но
  снятые данные в него не попадают.

### Excel учитывает выбор требований
- Excel-выгрузка теперь **учитывает выбор конкретных требований** (шаг 1 модалки), как и архивы:
  при подмножестве в `.xlsx` попадают только выбранные требования; при выбранных всех — весь проект.
  Ранее `.xlsx` игнорировал выбор требований и всегда выгружал проект целиком.

### API
- Единый контракт полей в `@po/core`: `EXPORT_OPTIONAL_FIELDS`, `parseExportFields`,
  `serialize(req, { fields })`.
- Endpoints принимают выбор полей: `GET /api/projects/:id/export?...&fields=...`,
  `POST /api/projects/:id/export/selected` (`fields` в теле), `GET /api/projects/:id/export.xlsx?fields=...`.
  Параметр `fields` отсутствует ⇒ все поля; пустой ⇒ минимум (только обязательные).
- `POST /api/projects/:id/export/selected` теперь принимает `format: 'xlsx' | 'zip' | 'targz'`:
  при `xlsx` возвращает книгу только с выбранными требованиями. `GET /export.xlsx` (весь проект)
  сохранён для случая «выбраны все».
