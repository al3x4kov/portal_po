# ADR-005 — Single-process: один Node-процесс отдаёт REST API и статику SPA

Статус: **Принято** · 2026-07-02 · Автор: Архитектор
Связано: `docs/overview/arch.md` §1 (общая схема), ADR-002 (MCP — отдельный процесс),
ADR-004 (конкурентность процессов на одном root).

## Контекст

Продукт — локальное приложение для одного Product Owner. Ему нужны привилегированные
ФС-операции, недоступные из браузера: создание каталогов проектов, чтение/запись `.md`,
упаковка/распаковка архивов. Поэтому чистый SPA невозможен — нужен локальный бэкенд.
Вопрос: разносить REST API и раздачу фронтенда на отдельные сервисы/порты или совместить.

## Решение

Один Node-процесс на Fastify обслуживает и `/api/*` (REST), и статический билд `apps/web`
(собранный SPA) — из одного процесса на localhost. Отдельного веб-сервера для статики нет.

**Обоснование:**

- **Простота запуска:** один порт, один процесс — минимальная операционная сложность для
  локального инструмента.
- **Нет CORS:** фронт и API на одном origin — не нужны CORS-настройки и preflight.
- **Путь к десктопу:** процесс позже оборачивается в Electron без переписывания логики
  (`docs/overview/arch.md` §1), фронт и API уже едины.

## Последствия / риски

- **Плюс:** минимум движущихся частей; единый origin; прямой путь к Electron-упаковке.
- **Минус / вне MVP:** горизонтальное масштабирование и многопользовательский режим не
  адресуются — один процесс на локальной машине. Это согласуется с моделью конкурентности
  LWW (ADR-004).
- MCP-сервер сюда **не** встраивается: это отдельный процесс с транспортом stdio
  (ADR-002), работающий над тем же `PROJECTS_ROOT` → межпроцессная конкуренция за
  `Projects/` регулируется ADR-004.
