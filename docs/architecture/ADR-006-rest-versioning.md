# ADR-006 — Версионирование REST-контракта и формата хранения

Статус: **Принято** · 2026-07-02 · Автор: Архитектор
Связано: ADR-001 (манифест `openspec/project.md`), `docs/architecture/api.md`
(`?format=`, OpenAPI), ARCH-5 / SA-9, OpenAPI `/docs`, `/openapi.json`.

## Контекст

Есть две разные оси совместимости, которые часто путают:
(1) **формат хранения** — структура файлов проекта на диске, у манифеста
`openspec/project.md` есть `schemaVersion` (ADR-001); (2) **REST-контракт** — сейчас
без версии в пути (нет `/v1/…`), но с расширяющим поведение параметром `format`
(`json` | `openspec`, см. `api.md`). Нужно единое правило, как эволюционировать оба,
не ломая существующих потребителей (в т.ч. ИИ-агентов).

## Решение

**(а) Формат хранения — `schemaVersion` в манифесте.**
Манифест `openspec/project.md` несёт `schemaVersion`; поле читается при чтении и импорте
проекта. Если `schemaVersion` ≠ текущей поддерживаемой — **явная ошибка** (миграции в MVP
нет); при импорте каталог проекта не создаётся (согласовано с атомарностью импорта в
`arch.md` §3.4). Молчаливого «чтения как есть» несовместимой версии не происходит.

**(б) Версия REST-контракта — через OpenAPI, без namespace в пути.**
Версия выражается полем `info.version` в OpenAPI (`/docs`, `/openapi.json`), а не префиксом
пути. Разрешены только **обратносовместимые** изменения (новые эндпоинты, новые
необязательные поля/параметры). **Ломающее** изменение оформляется как новый параметр или
новое поле — **не** молчаливая замена семантики существующего.

**(в) Расширение контракта через `?format=`.**
Новые представления ресурса добавляются query-параметром `format` (например `openspec`
дополнил `json`), без версионирования пути и без изменения дефолтного ответа.

## Последствия / риски

- **Плюс:** контролируемая совместимость; потребители (агенты, фронт) не ломаются
  «тихо»; расхождение версий хранилища ловится явной ошибкой, а не порчей данных.
- **Минус / риск:** отсутствие версии в пути REST требует дисциплины — любое изменение
  проверять на обратную совместимость (задача ARCH-5 / SA-9). При накоплении ломающих
  изменений в будущем может понадобиться `/v2/…` или content negotiation.
- Отсутствие миграций для `schemaVersion` в MVP означает: смена формата хранения = ручной
  перенос данных; план миграций — задел вне MVP.
