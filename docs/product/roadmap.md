# GO Product Roadmap — «Управление требованиями для PO»

> Дата: 2026-07-07 · Автор: draft по итогам совета (PO-3). **Статус: `[НА РЕВЬЮ PO]`.**
> Цель-ориентированный роадмап (Пихлер, GO Roadmap): каждый релиз описан через **Goal → Metrics →
> Features → Date**, а не как список фич. Отделён от бэклога задач (`docs/tasks/`). Даты и цели —
> черновые, на подтверждение PO.

## Принцип

Роадмап отвечает на вопрос «какую **продуктовую цель** закрывает релиз и как поймём успех», а не
«что делаем». Список задач и статусы поставки — в `docs/tasks/` и `docs/RELEASE_NOTES.md`.

---

## Релиз 1 — «MVP: файловый источник истины» ✅ (поставлено)

- **Goal:** PO может вести требования локально без БД и отдавать их машине.
- **Metrics:** активация — создать проект → 20 требований → экспорт; round-trip импорт/экспорт без
  потерь (см. `metrics.md`).
- **Features:** CRUD требований, дерево/связи, проверки целостности, импорт/экспорт (zip/tar.gz/xlsx),
  OpenSpec-экспорт, MCP-сервер.
- **Date:** поставлено (E1–E12, см. RELEASE_NOTES).

## Релиз 2 — «AI-ускоритель авторинга» ✅ (поставлено, легализовано v1.3)

- **Goal:** сократить время превращения сырой документации в структурированные ФТ/НФТ.
- **Metrics:** доля принятых AI-черновиков (acceptance-rate импорта/генерации); качество извлечения
  (провенанс, отсутствие домысливания) — см. `metrics.md`, порог «фича оправдана».
- **Features:** AI-конфиг/ключ, чат-помощник, генерация описания, AI-импорт из документации,
  пресеты моделей (FR-17…FR-20, ADR-007).
- **Date:** поставлено (E10/AI, todo_8/9/11/18); **легализовано в ТЗ v1.3 (2026-07-07)**.

## Релиз 3 — «Доверие и устойчивость» 🔄 (в работе — волны совета)

- **Goal:** продукт можно уверенно показывать/эксплуатировать: целостность под конкуренцией,
  предсказуемое поведение импорта, отсутствие рабочих тупиков.
- **Metrics:** 0 регрессий целостности под кросс-процессной нагрузкой; отсутствие потерь данных при
  импорте битых архивов; закрытые UX-тупики (удаление узла с детьми).
- **Features:** кросс-процессная сериализация (проверена тестом), защита импорта (bomb-guard,
  reject целостностно-битых архивов), каскадное удаление, документированная архитектура AI (ADR-007),
  graceful shutdown.
- **Date:** `[НА РЕВЬЮ PO]` — текущая итерация (Волны 0–3 совета, июль 2026).

## Релиз 4 — «Измеримость и продуктовая зрелость» ⏳ (следующий)

- **Goal:** перейти от «поставили фичи» к «понимаем ценность»: метрики, обратная связь, приоритеты.
- **Metrics:** заданы KPI активации/удержания и AI-acceptance; собирается обратная связь PO.
- **Features:** Vision Board/Roadmap/метрики (эта серия), перф-бюджеты импорта, покрытие тестами,
  согласованность требований; приоритизация AI по ценности/риску.
- **Date:** `[НА РЕВЬЮ PO]`.

## Кандидаты «позже» (не датированы) `[НА РЕВЬЮ PO]`

- Доступность (a11y/NFR-7): клавиатурная навигация дерева, доступный граф — **отложено** (решение
  PO: не критично для локального demo; вернуть при выходе к реальным пользователям).
- Безопасность AI-канала (secure-by-default TLS, шифрование ключа, NFR приватности) — **принятый
  риск** для локального demo (ADR-007); первая волна при переходе в прод/хостинг.
- Персистентность прогресса AI-импорт-джобы (ARCH-4) — при переходе к Electron/долгоживущему процессу.
- Репарентинг/подъём потомков при удалении (альтернатива каскаду), undo/история, импорт `.xlsx`.

## Обоснование инфраструктурных эпиков (PO-8) `[НА РЕВЬЮ PO]`

- **E14 — OpenAPI/Swagger (`/openapi.json`, `/docs`):** **оправдан**, роль-цель-выгода —
  *как потребитель API (фронтенд-клиент, ИИ-агент, будущие интеграции) я хочу машиночитаемый,
  версионируемый контракт REST, чтобы не гадать формы запросов/ответов и не расходиться с сервером*.
  Прямо поддерживает главную гипотезу (agent-ready), контракт-как-источник (ADR-006); ARCH-7 расширил
  его AI-эндпоинтами. Приоритет фактический — **Should** (не «фича ради полноты»).
- **E13 — сервисные функции:** `[НА РЕВЬЮ PO]` — сформулировать роль-цель-выгода под конкретную
  пользовательскую цель **или** перевести в **Could/Won't**, если ценность для целевого PO не
  подтверждается. Рекомендация совета: не держать в MVP без явной ценности.
