# Task 15 — привязка НФТ к ФТ (RELATES_TO) в AI-импорте

Постановка PO: НФТ должны получаться не только глобальными на проект, но и со связями с теми ФТ,
которые они ограничивают, — когда это ЯВНО следует из документации («время ответа поиска ≤ 200 мс»
— это НФТ про ФТ «Поиск»).

Факты домена (проверено):
- `RELATES_TO`/`DEPENDS_ON`/`BLOCKED_BY` разрешены между разными типами: `assertSameType`
  в LinkService вызывается только для иерархических типов (LinkService.ts:67).
- `assertNoCycle` вызывается для ВСЕХ типов связей (LinkService.ts:76) — backend-агенту проверить,
  как он трактует RELATES_TO (если учитывает все рёбра — возможны ложные CYCLE при перекрёстных
  привязках; тогда ловить DomainError → warn, как в populate сейчас).

Ключевое проектное решение: привязка извлекается ТОЛЬКО на этапе extraction (модель видит текст
фрагмента — есть доказательство). Structure-вызов текста НЕ видит и привязывать НФТ к ФТ не должен
(галлюцинации). Никакого нового вызова к AI hub не добавляем; стадии/прогресс не меняются.

## C1. Контракт (@po/core, ai.ts)
- `aiExtractedRequirementSchema`: новое опциональное поле
  `relatedFunctions: z.array(z.string().min(1).max(200)).max(20).optional()` —
  имена ФТ, которые данное НФТ явно ограничивает. Смысл только для type='NFR';
  для FUNCTION поле игнорируется на сервере (не ошибка валидации).
- `aiImportResultSchema`: новый счётчик `relatesLinks: z.number().int().min(0)` —
  создано связей НФТ→ФТ (RELATES_TO). Существующий `links` — только CHILD_OF, не переименовывать.
- Тесты в ai.test.ts.

## C2. Extraction-промпт (aiImportPrompt.ts)
В SYSTEM_PROMPT добавить правило (в стиле имеющихся):
- «Если НФТ явно ограничивает конкретные функциональные требования из ЭТОГО фрагмента или
  прямо называет функцию/раздел (например "поиск должен отвечать за 200 мс"), укажи их имена
  в поле relatedFunctions (массив имён ФТ ровно в той формулировке, в какой ты их извлёк).
  Только явные упоминания в тексте — не выводи связь из общих соображений. Если явной привязки
  нет — не добавляй поле вовсе.»
- Уточнить пример JSON-ответа в промпте (если там есть пример структуры — добавить поле).

## C3. Сервер (AiImportService)
- Агрегация дублей: у записей с одинаковым nameKey объединять relatedFunctions (union по
  nameKey('FUNCTION', имя), с сохранением первой встреченной формулировки имени).
- Populate, после существующего блока CHILD_OF:
  - для каждого НФТ с relatedFunctions: резолв ФТ по nameKey('FUNCTION', имя) в slugByKey
    (покрывает и созданные сейчас, и уже существовавшие в проекте ФТ);
  - не найдено → warn `НФТ «X»: связанная ФТ «Y» не найдена — связь пропущена.`;
  - найдено → `linkService.create({ sourceSlug: nfrSlug, type: 'RELATES_TO', targetSlug: ftSlug })`;
    info `Связано: НФТ «X» → ФТ «Y» (RELATES_TO).`; counters.relatesLinks += 1;
  - идемпотентность/re-run: как у CHILD_OF — для пропущенных существующих НФТ докомплектовывать
    недостающие RELATES_TO, уже существующую связь (в любом направлении: у НФТ смотреть и
    RELATES_TO-парную запись) не трогать и не дублировать;
  - DomainError (конфликт/цикл/лимиты) → warn, не валить job (паттерн уже есть);
  - cancel учитывать в цикле создания связей;
  - самосвязь НФТ→НФТ невозможна по построению (target всегда FUNCTION) — но защититься от
    записи FUNCTION с relatedFunctions: поле игнорировать с warn
    `«X» (FUNCTION): relatedFunctions игнорируется — привязка допустима только от НФТ.`
- Итоговые сообщения: в done/cancel-сводках добавить `связей НФТ→ФТ: N` рядом с «связей: M».
- Сводка дерева (B6) не меняется — RELATES_TO в дерево не входит.

## C4. Фронт (apps/web, после бэка)
- AiImportModal: в успешной сводке и сводке остановки показать новый счётчик
  («Связей НФТ→ФТ: N») — рядом с существующим счётчиком связей; data-testid по образцу соседних.
- Компонентный тест на отображение счётчика.

## C5. E2E (e2e/, после фронта)
- ai-stub: extraction-ответ с НФТ, у которого `relatedFunctions` (валидная ФТ + несуществующая).
- Сценарии:
  1. НФТ→ФТ связь создана: через API у НФТ есть RELATES_TO на ФТ (и парная у ФТ), в логе
     «Связано: НФТ … → ФТ … (RELATES_TO)», счётчик в модалке;
  2. несуществующая ФТ → warn «связанная ФТ … не найдена — связь пропущена», job успешен;
  3. повторный импорт (идемпотентность): связь не дублируется, счётчик relatesLinks=0 на re-run;
  4. обновить существующие ассерты, если задеты (happy-path сводка и т.п.).
- ai-mockserver.spec: extraction-expectation дополнить relatedFunctions, ассерт связи.

## Качество/гипотезы, которые тесты должны подтвердить
- Unit: схема (валид/инвалид relatedFunctions), union при дублях, резолв по регистронезависимому
  имени, привязка к СУЩЕСТВУЮЩЕЙ в проекте ФТ (не из импорта), warn при неизвестной ФТ,
  идемпотентность re-run, FUNCTION с relatedFunctions → warn+игнор, DomainError → warn,
  cancel между связями, счётчик relatesLinks в result и в done-сводке.
- E2E: сквозное подтверждение связи в файлах проекта (parity обеих сторон) и в UI.
