# task26 — Подсветка непроверенных ИИ-требований в дереве

## Проблема (обратная связь пилота)

После AI-импорта (документация или бэклог) созданные ФТ/НФТ визуально не отличаются
от выверенных вручную: в общем дереве всё единообразно, и PO не понимает, что уже
провалидировано, а что нет.

## Решение (решения PO, 2026-08-04)

Требования, созданные ИИ, по умолчанию подсвечены как «не проверено». PO заходит в
карточку требования и снимает отметку — подсветка уходит, значит валидация проведена.

Гейт PO закрыл развилки:
1. Снятие отметки — **только в карточке требования** (массовые действия — вне объёма v1).
2. Признак ставится **только новым импортам**; ретро-миграции уже загруженных
   требований нет (старые файлы без полей — не подсвечены).
3. Отметка **обратима** — переключатель «проверено / не проверено».
4. В дереве нужен **фильтр «только непроверенные»** и **счётчик** непроверенных.

## Контракт (@po/core)

Два новых опциональных поля `Requirement` (и во frontmatter `.md`):

- `origin?: 'AI_DOCS' | 'AI_BACKLOG'` — происхождение. Проставляется ТОЛЬКО сервером
  при populate соответствующего импорта. Отсутствие = создано человеком.
- `aiValidated?: boolean` — человек проверил. При создании импортом не ставится
  (эквивалент `false`).

**Производное состояние подсветки:** `origin != null && aiValidated !== true`.
Хелпер в core (например `isAiPendingReview(req)`) — единственный источник правила,
фронт его потребляет, не дублирует.

Совместимость: старые `.md` без полей читаются как «создано человеком»; round-trip
markdown остаётся lossless; в схемах создания/обновления `origin` менять НЕЛЬЗЯ
(игнорируется/400 — на усмотрение реализации, зафиксировать тестом), `aiValidated`
принимается в update.

## Сервер

- `populate` документного импорта → `origin: 'AI_DOCS'`; populate бэклога →
  `origin: 'AI_BACKLOG'` (в т.ч. для узлов, созданных импортом).
- `PUT /api/projects/:id/requirements/:rid` принимает `aiValidated` (true/false).
- Ничего больше не меняется: удаление/связи/экспорт — как есть (новые поля просто
  переживают round-trip и попадают в экспорт).

## UI

1. **Дерево (TreeTable):** строки в состоянии «ИИ, не проверено» подсвечены —
   мягкая заливка строки (токен на основе `--color-info-bg`/`--color-warning-bg`,
   выбрать читаемый в обеих темах) + компактный бейдж «ИИ» с тултипом
   «Создано ИИ, не проверено» (не только цвет — НФТ доступности: цвет + метка).
   Проверенные ИИ-требования выглядят как обычные.
2. **Карточка требования (RequirementModal):** для требований с `origin` — блок
   «Проверка» с переключателем «Проверено» (вкл = `aiValidated: true`), подпись
   поясняет, что снимает подсветку в дереве; для созданных вручную блока нет.
   Сохраняется существующим механизмом сохранения карточки (мгновенный autosave
   или кнопка — как в текущем UX).
3. **Фильтр и счётчик:** в панели фильтров дерева — переключатель «Только
   непроверенные (ИИ)»; рядом с фильтрами/в шапке — счётчик «Не проверено: N»
   (по обоим разделам ФТ/НФТ, с учётом текущих фильтров показывать общий счётчик
   проекта — зафиксировать в реализации и тесте). Счётчик кликабелен = включает фильтр.
4. Терминология в UI: «не проверено» / «проверено» (не «валидировано»).

## Критерии приёмки

1. После AI-импорта документации все созданные ФТ/НФТ подсвечены и имеют бейдж «ИИ».
2. После AI-импорта бэклога — то же (включая созданные импортом узлы).
3. В карточке ИИ-требования есть переключатель; включение убирает подсветку в дереве
   без перезагрузки; выключение возвращает.
4. У требования, созданного вручную, переключателя нет и подсветки нет.
5. Фильтр «только непроверенные» оставляет в дереве непроверенные ИИ-строки
   (+ предки для контекста, как у существующих фильтров); счётчик показывает их число
   и обнуляется по мере снятия отметок.
6. Старые проекты (файлы без новых полей) выглядят как раньше — ничего не подсвечено.
7. Round-trip `.md` сохраняет поля; экспорт/импорт архива их переносит.
8. Гейты качества зелёные; покрытие core ≥90%.

## Вне объёма

Массовое снятие (ветка/выделение), ретро-миграция старых требований, отдельная
история проверок/кто проверил, подсветка в других экранах (дашборд, граф).
