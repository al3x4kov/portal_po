## A1 (задача 2) — длинные пути на «Открыть существующий проект»

Проблема: путь до каталога проекта (PROJECTS_ROOT/<имя>) может быть длинным; текущие блоки
списка узкие, путь ломает вёрстку или нечитаем.

Решение PO:
- Расширить контейнер списка проектов (использовать доступную ширину экрана, как минимум max-w-3xl/4xl вместо узкого).
- Путь: моноширинный вторичный текст, усечение с многоточием (`truncate`) + полный путь в `title`;
  при этом имя проекта всегда видно полностью (перенос допустим для имени, не для пути).
- Ничего не менять в API/данных.

Критерии приёмки:
- Путь из ~120 символов не разрушает сетку, виден его конец или начало + `title` с полным путём.
- Существующие тесты OpenExisting зелёные, добавлен компонентный тест на длинный путь.

## A2 (задача 5) — колонка «Требование» в TreeTable

Проблема: имена ФТ/НФТ длинные, колонка узкая.

Решение PO:
- Колонка «Требование» получает приоритетную (гибкую) ширину — остальные колонки фиксированные/по содержимому.
- Длинное имя: усечение с многоточием + полный текст в `title`; иерархический отступ сохраняется.
- Горизонтального скролла страницы быть не должно.

Критерии приёмки:
- Имя ~100 символов: строка одной высоты, текст усечён, `title` содержит полное имя.
- Существующие тесты TreeTable зелёные + тест на длинное имя.

## A3 (задача 3) — повторный запрос списка моделей и смена модели

Места: экран «AI» (AiPage), виджет чата (ChatWidget), модалка «AI подгрузка ФТ и НФТ из
документации» (AiImportModal). Сейчас после первой загрузки списка моделей и выбора модели
повторный запрос не предусмотрен.

Решение PO:
- Рядом с селектом модели — кнопка «Обновить список» (иконка refresh, data-testid вида
  `ai-models-refresh`), доступная всегда, когда есть ключ/подключение; во время запроса — спиннер/disabled.
- После обновления: если выбранная модель осталась в списке — выбор сохраняется; если исчезла —
  выбирается дефолтная/первая, пользователю показывается ненавязчивое уведомление (текст в UI, не только toast).
- Селект модели остаётся активным после выбора — модель можно сменить в любой момент.
- Единая логика через общий hook (api/hooks.ts, refetch React Query), без дублирования в трёх компонентах.
- Контракт API не меняется (используется существующий endpoint списка моделей).

Критерии приёмки:
- В каждом из трёх мест: кнопка обновления перезапрашивает список; смена модели применяется к последующим запросам.
- Компонентные тесты: refetch, сохранение выбора, сброс исчезнувшей модели.

## B1 (задача 1) — удаление проекта со страницы «Открыть существующий проект»

### Backend (волна 1, владелец контракта)
- `DELETE /api/projects/:id` → 204 при успехе; 404 если проекта нет; 400 при невалидном id.
- Слои: route (парсинг/маппинг ошибок) → ProjectService.deleteProject → FsProjectRepo (рекурсивное
  удаление каталога проекта строго внутри PROJECTS_ROOT через pathSafe — NFR-5).
- Удаление проекта удаляет все его требования вместе с каталогом; отдельной чистки связей не
  требуется (связи живут в .md файлах проекта), но проверить, нет ли внешних индексов.
- TDD: сначала тесты (integration против temp dir): успех, 404, path traversal (`../`), повторное удаление.

### Frontend (волна 2, после A1 и B1-BE)
- В каждой строке списка проектов — кнопка удаления (иконка корзины, `data-testid="project-delete"`),
  не конфликтующая с кликом «открыть».
- Клик → ConfirmDialog: заголовок «Удалить проект», текст «Проект „<имя>“ и все его файлы будут
  удалены с диска. Действие необратимо.» Кнопки «Удалить» (danger) / «Отмена».
- Подтверждение → DELETE → инвалидация списка проектов; если удалён текущий выбранный проект в
  ui-store — сбросить выбор; toast об успехе; ошибка — toast с текстом ошибки, диалог закрыт.

Критерии приёмки:
- Отмена ничего не удаляет. Удаление убирает проект из списка без перезагрузки страницы.
- e2e: создать проект → открыть существующий → удалить с подтверждением → проекта нет; сценарий отмены.

## B2 (задача 4) — опциональный AI-шаг связей ФТ↔НФТ в AI-импорте

### Backend (волна 1, владелец контракта)
- В контракт запуска импорта добавить опциональный boolean-флаг (имя выбрать по существующему
  стилю контракта, например `inferLinks`, default false) — в Zod-схеме @po/core, если схема
  запроса импорта живёт там; иначе в серверной схеме, но единообразно с текущим контрактом.
- Если флаг включён: ПЕРЕД текущим последним шагом пайплайна импорта выполняется новый шаг
  «Проставление связей ФТ↔НФТ»: запрос в AI Hub, вход — уже созданные ФТ/НФТ (id+имя+краткое
  описание), выход — список пар для RELATES_TO по смыслу.
- Жёсткие гарантии: шаг НЕ создаёт и НЕ изменяет требования; связи только между реально
  существующими id (выдуманные — отбрасывать), только валидные по правилам графа (@po/core
  graph/integrity: без self-link, дублей, недопустимых типов); уже существующие связи (в т.ч. из
  явных упоминаний, фича 6b3327e) не дублировать.
- Ошибка/таймаут AI-шага НЕ валит импорт: шаг помечается как пропущенный/частичный, импорт
  завершается; в статусе джобы это видно.
- Прогресс: новый шаг отражается в статусах джобы (AiImportJobs), чтобы фронт показал этап.
- TDD: unit на фильтрацию выдуманных id/дублей/self-link, на порядок шагов (перед последним), на
  деградацию при ошибке AI; AI-клиент мокается.

### Frontend (волна 2, после A3 и B2-BE)
- В AiImportModal — чекбокс (default off): «Дополнительно проставить связи между ФТ и НФТ
  (возможны галлюцинации) — без добавления новых ФТ/НФТ», `data-testid="ai-import-infer-links"`.
- Флаг уходит в запрос запуска импорта; в прогрессе отображается дополнительный шаг с его статусом
  (включая «пропущен из-за ошибки», если бэкенд так ответил).

Критерии приёмки:
- Выключен — поведение импорта байт-в-байт прежнее (регрессия покрыта существующими тестами).
- Включён — в результате появляются только RELATES_TO связи между существующими ФТ/НФТ; количество
  требований не меняется.

## Общие правила для всех исполнителей
- Сначала `graphify query/explain`, потом чтение/правка файлов.
- Владение: backend = @po/core + apps/server (+тесты); frontend = apps/web; QA = e2e/.
- Не коммитить и не запускать `graphify update` (делает оркестратор). Полный e2e гоняет QA-волна.
- Backend: TDD. Frontend: компонентные тесты Vitest рядом с компонентом.
- Прогонять локально только свой скоуп: `npx vitest run <файлы>` + `npm run typecheck`.
