# task22 — Импорт zip/tar.gz с корневым каталогом-обёрткой (пилотный баг №1)

## Проблема

Импорт архива проекта (`POST /api/projects/import`) падает с ошибкой
«Archive has no openspec/specs directory.» на архивах, упакованных «папкой» —
например `Gitea 1.19.0.zip`, где всё содержимое лежит под единственным корневым
каталогом `Gitea 1.19.0/openspec/...`. Та же папка, положенная руками в
`Projects/`, открывается без проблем.

## Причина

`apps/server/src/repositories/ArchiveRepo.ts`: после распаковки `validate()` и
дальнейшие шаги ищут `openspec/project.md` и `openspec/specs` строго в корне
распакованного содержимого (`ArchiveRepo.ts:37-38`, `:408`). Обёртка-каталог не
учитывается, хотя это стандартное поведение zip, создаваемого из папки
(macOS Finder, GitHub releases и т.д.).

## Что сделать

1. В `ArchiveRepo` после распаковки определить фактический content root:
   - если в корне есть `openspec/` — как сейчас;
   - иначе, пока в текущем каталоге ровно один подкаталог (служебные записи вроде
     `__MACOSX`, `.DS_Store` игнорировать) — спуститься в него и проверить снова;
     глубина спуска разумно ограничена (например 3 уровня);
   - если `openspec/` так и не найден — прежняя ошибка `ArchiveError`, но с
     текстом, объясняющим ожидаемую структуру («архив должен содержать каталог
     openspec/ с project.md и specs/», допускается одна папка-обёртка).
2. Поведение одинаково для zip и tar.gz.
3. Безопасность путей (защита от path traversal, NFR-5) не ослабляется: спуск —
   только по фактически распакованным подкаталогам внутри temp-каталога.
4. Экспорт не меняется.

## Критерии приёмки

- Zip с структурой `wrapper/openspec/{project.md,specs/...}` импортируется; имя
  проекта берётся как раньше (из запроса/имени архива — существующее поведение
  не менять, обёртка на имя не влияет).
- Zip с `openspec/...` в корне — работает как раньше (регресс нет).
- Zip c двойной обёрткой `a/b/openspec/...` — импортируется (в пределах лимита глубины).
- Zip с `__MACOSX/` рядом с обёрткой — импортируется.
- Архив вообще без `openspec/` — понятная ошибка (см. п.1), джоба/каталог не
  создаются (атомарность как сейчас).
- tar.gz-варианты тех же случаев — аналогично.
- Unit-тесты на все случаи в тестах ArchiveRepo (TDD: сначала красные тесты).
