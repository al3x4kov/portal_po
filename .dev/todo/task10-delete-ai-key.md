# Task 10: удаление сохранённого API-ключа AI Hub

Происхождение: вне-скоупная находка QA в task 9 — `PUT /api/ai/config` игнорирует пустой
`apiKey` (осознанное решение task 8: «пустое поле — ключ не трогаем»), поэтому удалить
сохранённый ключ невозможно ни из UI, ни через API (e2e обходили удалением файла с диска).

## Решения PO

1. Контракт: `apiKey` в `aiConfigUpdateSchema` становится `string | null | undefined`:
   - `undefined` и `''` — как раньше, ключ НЕ трогаем (семантика task 8 сохраняется);
   - `null` — удалить сохранённый ключ.
2. UI (экран AI): когда ключ сохранён — рядом с полем ключа кнопка «Удалить ключ»
   с подтверждением (существующий ConfirmDialog). После удаления: статус «ключ удалён»,
   `hasApiKey=false`, экран возвращается в пустое состояние («Введите API-ключ…»),
   виджет чата автоматически становится серым (общий config-запрос инвалидируется).
3. Модели проектов (`modelByProject`) при удалении ключа НЕ трогаем — ключ вернут, модель
   останется выбранной.

## Волны

- Backend: схема в `@po/core` + `AiConfigRepo.update` (null → удалить) + тесты (TDD).
- Frontend: кнопка + confirm + инвалидация; component-тесты.
- QA: e2e — сохранить ключ → удалить → пустое состояние AI-экрана и серый чат;
  по возможности перевести сброс конфига в chat-widget.spec.ts с удаления файла на API.
