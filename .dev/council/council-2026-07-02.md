## Кросс-дисциплинарный консенсус (несколько экспертов независимо → высокий приоритет)

1. **Целостность многофайловых операций** — `ARCH-1` (Blocker) == `BE-7` (Medium): запись пары
   реципрокных связей и каскадное удаление не атомарны → односторонние/висячие связи при сбое.
2. **Модель конкурентного доступа к `Projects/`** — `ARCH-2` == `QA-3` == `SA-8`: UI и агенты
   (REST/MCP) пишут один `PROJECTS_ROOT` без блокировок → lost-update/повреждение манифеста.
3. **Рассинхрон «источника истины» (ТЗ ↔ ADR/код)** — `BA-1` (Blocker) + `BA-5` + `SA-5` + `SA-7`
   + `ARCH-8`: §2.2/2.3/2.5 `project.md` описывают ULID/targetId/frontmatter, а код — slug/OpenSpec.
4. **Уровень `BLOCKER` не задан в требованиях** — `BA-2` == `SA-5` (код имеет 5 значений, ТЗ — 4).
5. **Неизмеримые НФТ / нет fit-критериев** — `BA-4` == `SA-2` (+ носитель критерия в модели `SA-4`).
6. **Доступность (a11y)** — дефекты: `UX-5` (focus-trap/возврат фокуса), `UX-9` (контраст < WCAG AA);
   отсутствие тестов: `QA-1`.
7. **Web-покрытие не измеряется и не гейтится** — `QA-4` == `BE-10`.
8. **Дублирование через границы (правила/метки/дерево/контракт)** — `BE-2`+`BE-3`+`BE-4` == `ARCH-4`.
9. **«Битые» файлы не видны в UI и игнорируются в write-path** — `SA-6` (UI) == `ARCH-3` (запись).
10. **FR-набор неполон относительно построенного (E15/E16), FR как фичи, а не use cases** —
    `BA-3` == `SA-3`.
11. **Версионирование схемы/контракта (`schemaVersion=2` не проверяется)** — `ARCH-5` == `SA-9`.
12. **ИИ-агент как второй пользователь/стейкхолдер не оформлен** — `PO-7` == `SA-11` (корень — `SA-1`).
13. **Защита импорта (bomb/limits/tar-traversal)** — `QA-8` == `ARCH-10`.

## Кросс-дисциплинарные конфликты/напряжения (решать явно, не «усреднять»)

- **PO-2/PO-5 vs остальные:** Пихлер предупреждает — не вкладываться в новый output (E13/E14/E16),
  пока не подтверждён outcome (гипотеза AI-ready). Остальные предлагают ещё 60+ задач-доработок.
  **Решение председателя:** различать *дефекты корректности/целостности/доступности* (делать —
  это не «полировка») и *новые инвестиции в фичи* (гейтить через PO-2/PO-3). Совет выдал задачи;
  порядок их запуска подчинить приоритету ценности и риска, а не «сделать всё».
- **UX-1 (показывать действия строки всегда) vs недавнее решение E16** (действия по hover,
  расширенная колонка). Норман: hover-скрытие бьёт по discoverability и клавиатуре. Пересмотреть.
- **UX-4 (превентивная фильтрация несовместимых связей на клиенте) vs BE/ARCH** (сервер —
  последний рубеж истинности). Не конфликт по сути: сервер остаётся авторитетом, UI добавляет
  раннюю профилактику. Реализовать через общий предикат целостности (см. BE-2/ARCH-4).

## UX — Дон Норман (человеко-центрированный дизайн)

  сфокусированной строки) [ ] Tab делает сфокусированную кнопку видимой [ ] одинаково desktop/mobile.

  LinkModal не фильтрует цели по типу/циклу/одному родителю. Приёмка: [ ] для CHILD_OF/PARENT_OF
