# DESIGN — todo_22 (AI-импорт бэклога)

Первоисточник для гитигнорящегося `design-out/todo22/`.

## Экраны

| # | Файл | Состояние | Закрывает |
|---|------|-----------|-----------|
| 1 | screens/01-upload-preview.html | Кнопка рядом с «AI подгрузка из документации» + загрузка/предпросмотр/мини-смета | П1, П2 |
| 2 | screens/02-progress.html | Прогресс: батч X из Y, счётчики (вкл. «дублей пропущено»), события | П5.1 |
| 3 | screens/04-review.html | **Выверка разметки** (гейт записи, решение PO №1): новые бизнес-узлы + чекбоксы строк + «Записать в проект» | Решения PO |
| 4 | screens/03-report.html | Итоговый отчёт: счётчики + таблица соответствий | П5.3 |

После гейта PO: узла-свалки «Бэклог» нет — только бизнесовые узлы (существующие или
новые, предложенные моделью); target из файла или полем на предпросмотре; источник —
новый тип BACKLOG; запись в проект только после явного подтверждения на шаге выверки.

## Решения

- Модалка — тот же каркас и размер (~70%, task24), что у AiImportModal; лента событий
  растягивается по высоте (flex, role="log", tabindex).
- **Ошибка отдельно не макетируется** — точный реюз паттерна todo20
  (`design-out/todo20/screens/04-error.html`): код/действие/счётчики/«Продолжить»/детали.
- Таблица соответствий: исходная формулировка (с ключом моноширинно) → бизнес-имя →
  родитель; бейджи «дубль» (warning), «НФТ» (info), «без родителя» (нейтральный).
- Распознанные колонки — чипы «Ключ: A — Issue key» / «Формулировка: B — Summary».
- Терминология: «батч» в логе, «строка» в счётчиках; «фрагмент» не используется
  (это термин документного импорта).
