## ЕДИНЫЙ КОНТРАКТ (E1) — все изменения `packages/core/src/validation/ai.ts`

Расширения (обратная совместимость обязательна — старые клиенты/конфиги работают):

1. `aiModelPresetSchema` + новые поля (все с дефолтами через `resolveModelPreset`):
   - `parallelism: int 1..8` (дефолт 2) — пул одновременных вызовов (C2);
   - `perCallTimeoutSec: int ≥10` (дефолт 120) — тайм-аут вызова (C3);
   - `runBudgetTokens: int ≥0 | null` (дефолт null = без лимита) — бюджет прогона (B6);
   - `estimateThresholdTokens: int ≥0 | null` (дефолт 2_000_000; 0 = подтверждать всегда,
     null = никогда) — порог сметы (A4, решение PO №2).
2. `AI_IMPORT_MAX_ARCHIVE_BYTES` → **200 МБ** (решение PO №1); новый
   `AI_IMPORT_MAX_TEXT_FILES = 2000`.
3. Классы источников: `AI_IMPORT_SOURCE_CLASSES = ['release-notes','user-guide',
   'admin-guide','security','api-spec','config','other'] as const`.
4. Опись: `aiImportInventoryViewSchema` — `{ totalFiles, processed: {class → count},
   excluded: [{ pattern|path, reason, count }] }` (агрегированная, не по-файловая).
5. Смета: `aiImportEstimateViewSchema` — `{ files, chunks, calls, tokens, thresholdTokens,
   overThreshold: boolean }`.
6. Usage: `aiImportUsageViewSchema` — `{ promptTokens, completionTokens }`.
7. Ошибка джобы (расширение существующего `error`): `{ message, hint, code, category:
   'data'|'model'|'network'|'config'|'budget', action, resumable: boolean }` — `code/
   category/action/resumable` НОВЫЕ обязательные при fail; message/hint сохраняются.
8. Прогресс: в `aiImportJobViewSchema` добавить optional `currentFile`,
   `currentClass`, `chunkIndex`, `chunkTotal`, `etaSeconds: number|null`,
   `usage`, `inventory`, `estimate`, `report`.
9. Статусы: `AI_IMPORT_STATUSES` + `'awaiting-confirmation'` (смета выше порога) и
   `'interrupted'` (обнаружена после рестарта). Существующие не переименовывать.
10. Отчёт качества: `aiImportReportViewSchema` — `{ coverage: [{ sourceClass, files,
    processedFiles, extractedFunctions, extractedNfrs, retriedChunks }], blindSpots:
    [{ kind: 'skipped-file'|'truncated'|'excluded', message, count }] }`.
11. История: `aiImportJobSummarySchema` — `{ jobId, projectId, status, startedAt,
    finishedAt?, result?, resumable }` + `aiImportJobListSchema = { jobs: [...] }`.
12. Таксономия кодов: `AI_IMPORT_ERROR_CODES` реестр (минимум: `CFG-01` нет ключа/модели,
    `CFG-02` 401/403, `CFG-03` 404 model, `DATA-01` архив без текстовых файлов, `DATA-02`
    превышен размер/число файлов, `NET-01` 429 исчерпаны ретраи, `NET-02` 5xx исчерпаны,
    `NET-03` таймауты исчерпаны, `MODEL-01` невалидный JSON после всех попыток и делений,
    `MODEL-02` context_length на минимальном фрагменте, `BUDGET-01` бюджет исчерпан) —
    каждый с русским `message`, `action`, `category`, `resumable`.

### API (routes `apps/server`, все схемы — из @po/core)

- `POST /api/projects/:id/ai-import` — как сейчас (multipart), но: job проходит стадии
  `inventory → estimate`; если смета выше порога → статус `awaiting-confirmation` (LLM-вызовы
  дальше НЕ идут); иначе сразу дальше.
- `POST /api/ai-import/:jobId/confirm` — подтвердить старт после сметы (409, если статус не
  `awaiting-confirmation`).
- `POST /api/ai-import/:jobId/resume` — возобновить `failed | cancelled | interrupted`
  (404/409 иначе); продолжает с чекпоинта.
- `GET /api/projects/:id/ai-import/jobs` — история джоб проекта (решение PO №4).
- `GET /api/ai-import/:jobId/log` — полный лог файлом (text/plain, attachment).
- `GET /api/ai-import/:jobId` — как сейчас, расширенный view.

### Чекпоинты (решение PO №3)

`Projects/<project>/.ai-jobs/<jobId>/` — `state.json` (позиция в описи, extracted-записи,
usage, адаптивное состояние чанкера, лог). Каталог `.ai-jobs`:
- исключается из экспорта архива (zip/targz) и из импорта;
- игнорируется при чтении требований/описи проекта;
- переживает рестарт сервера: при старте сервер сканирует `.ai-jobs` и поднимает
  незавершённые джобы в статус `interrupted`.

## Эпик E2: Подготовка данных (A1–A4) · Трассировка: П1, П2

#### T-202 · Инвентаризация и контентный триаж · [L] · после T-201
- **Что:** новая стадия inventory: потоковый обход распакованного каталога; определение

- **Критерии приёмки:**
  - [ ] Классы НЕ зависят от имён каталогов/файлов (тест: те же файлы с «неговорящими»
        именами → те же классы; кириллица в путях).

  - [ ] Потоково: файл читается один раз, не грузим весь архив в память (Н1).
  - [ ] LLM-классификация опциональна: при недоступности модели все неопознанные → `other`
