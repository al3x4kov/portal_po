## Проблемы по критичности
### 🟠 Высокие (закрыты архитектурными решениями)
- **Место хранения справочников.** БД нет. → `[ДОБАВЛЕНО]` `Projects/<id>/dictionaries.json`, владелец — новый `FsDictionariesRepo` (apps/server). Создаётся при создании проекта с дефолтным приоритетом «Квартальная цель».
- **Целостность priorityId.** → `[ДОБАВЛЕНО]` При сохранении требования сервер проверяет существование `priorityId` каждого источника; удаление используемого приоритета — с обязательной заменой (`reassignTo`).
- **Сериализация sources[]/releaseDate.** → `[ДОБАВЛЕНО]` В frontmatter требования (gray-matter), round-trip lossless (тест как для scenarios).

### 🟡 Средние
- **Автосбор источников «сразу при вводе»** — создание записи справочника из combobox до сохранения требования; «черновые» имена приняты PO осознанно.
- **Дубликаты по имени.** → `[ДОПУЩЕНИЕ]` Имя приоритета и имя источника уникальны в проекте (case-insensitive, trim).

## Неоднозначности
| Формулировка | Трактовки | Принятая |
|---|---|---|
| «RICE = max по источникам» | max score / по старшему приоритету | max числового score |
| «палитра из токенов» | любой токен / выделенный набор | фиксированный набор PRIORITY_COLORS (8) в @po/core |
| «дата вне квартала» | ошибка / предупреждение | бледное предупреждение, не блокирует |

## Принятые допущения
- `[ДОПУЩЕНИЕ]` Цвет приоритета — ключ палитры (`'red'|'amber'|…`), не HEX.
- `[ДОПУЩЕНИЕ]` `releaseDate` подчиняется правилу target: при `implemented=true` очищается.
- `[ДОПУЩЕНИЕ]` Меньший `order` = старше (для агрегата приоритета).
- `[ДОПУЩЕНИЕ]` Combobox-автосбор создаёт источник типа по выбору (дефолт TEXT), имя из ввода.
