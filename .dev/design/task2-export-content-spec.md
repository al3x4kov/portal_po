## 1. Модель выбора данных

**Группа 1 «Обязательные данные»** — всегда в выгрузке, чекбоксы `checked + disabled` (отжать нельзя):
| UI-элемент | Поле домена | Excel-колонка | OpenSpec .md |
|---|---|---|---|
| Название | `name` | «Требование» (с отступом по дереву) | заголовок `### Requirement: <name>` |
| Критичность | `criticality` | «Критичность» (+заливка цветом) | `- criticality:` |
| Статус реализации | `implemented` (+`targetQuarter`/`targetYear`) | «Реализация» (`Реализовано` / `Q<n> <год>`) | `- implemented:` (+`- target:` когда `false`) |

**Группа 2 «Дополнительные данные»** — только если чекбокс включён:
| UI-элемент | Поле домена | Excel-колонка | OpenSpec .md |
|---|---|---|---|
| Источник требования | `source` | «Источник» | `- source:` |
| Описание | `description` (+ сценарии, см. §4) | «Описание» | тело md (+ `#### Scenario:`) |
| Справочная информация | `infoItems[] {type,value}` | «Справочная информация» | `#### Info` |
| Связи | `links[]` | «Связи» | `#### Links` |

**Структурные поля вне чекбоксов** (техническая необходимость, всегда присутствуют):
- Excel: колонка «Тип» (ФТ/НФТ) — идентификация вида требования, идёт сразу после «Требование».
- .md: `- createdAt:` / `- updatedAt:` — нужны для валидного parse() при обратном импорте.

## 2. Excel (.xlsx)

Стиль сохраняем и улучшаем: **один лист «Требования», 1 строка = 1 требование**, порядок
`orderTree(ФТ)` затем `orderTree(НФТ)`, отступ имени по глубине дерева, жирная строка заголовков,
заливка ячейки «Критичность» цветом критичности.

**Колонки строятся динамически** из выбора. Базовый неизменяемый префикс, затем — выбранные
опциональные, в фиксированном порядке:

```
[Требование] [Тип] [Критичность] [Реализация]  → всегда
   ├─ [Источник]                → если выбран «Источник»
   ├─ [Описание]                → если выбрано «Описание»
   ├─ [Справочная информация]   → если выбрана «Справочная информация»
   └─ [Связи]                   → если выбраны «Связи»
```

Рендеринг ячеек:
- **Реализация:** `Реализовано` | `Q<n> <год>` (как сейчас) | пусто, если нет target.
- **Источник:** значение `source` как есть; пусто → пустая ячейка.
- **Описание:** markdown-текст `description` дословно (без рендера), `wrapText: true`; пусто → пусто.
- **Справочная информация:** элементы `infoItems` как `«<type>: <value>»`, по одному в строке
  внутри ячейки (перенос строки `\n`, `wrapText: true`); пусто/нет → пустая ячейка.
- **Связи:** как сейчас `formatLinks` — `<фраза> «<имя цели>»`, соединять `; `; пусто → пусто.

Ширины колонок: сохранить текущие (Требование 44, Тип 8, Критичность 14, Реализация 16,
Описание 50, Связи 50); Источник ≈ 18, Справочная информация ≈ 40.

Улучшения (опционально, на решение архитектора — вынести отдельными подзадачами, не блокеры):
- закрепить строку заголовков (freeze top row);
- автофильтр по строке заголовков;
- `vertical: 'top'` для многострочных ячеек (Описание/Справочная/Связи).

**Крайний случай:** если пользователь снял все опциональные — лист содержит только
`Требование | Тип | Критичность | Реализация`. Это валидная минимальная выгрузка.

## 3. zip / tar.gz (OpenSpec .md)

Архив упаковывает по одному `.md` на требование в `openspec/specs/{functions|nfr}/<slug>.md`
(+ существующая обвязка проекта/манифест — сохраняем). Формат файла — `serialize()` из
`markdown.ts`. Выбор данных управляет тем, какие секции попадают в файл:

Всегда:
```
### Requirement: <name>
- criticality: <crit>
- implemented: <true|false>
- target: Q<n> <год>        # только если implemented=false
- createdAt: <iso>          # техническое, всегда
- updatedAt: <iso>          # техническое, всегда
```
Опционально (секция появляется только если ВЫБРАНА и значение непустое):
```
- source: <source>          # если выбран «Источник» и source задан

<описание>                  # если выбрано «Описание»; + блоки #### Scenario: (см. §4)

#### Links                  # если выбраны «Связи» и links непусты
- <TYPE>: <targetSlug>      # (уже фильтруются на множество экспортируемых, generateTracker-логика)

#### Info                   # если выбрана «Справочная информация» и infoItems непусты
- <type>: <value>
```

Пустые опциональные секции НЕ выводим (никаких пустых `#### Info`/`#### Links`).

⚠️ **Round-trip (на валидацию/архитектору):** отфильтрованный архив — это «выгрузка для чтения»,
а не обязательно лосслесс-снимок. При снятых опциональных секциях обратный импорт потеряет эти
данные. `createdAt/updatedAt` оставляем всегда, чтобы `parse()` не падал. Рекомендация: если
хотим сохранять лосслесс-снимок — оставить пользователю понимание через превью-подсказку
(«архив будет содержать только выбранные данные»). Полный лосслесс-экспорт = выбрать все опции.

## 4. Правила поведения (единые для всех форматов)

1. Обязательные поля (Группа 1 + Тип + createdAt/updatedAt) — всегда, независимо от чекбоксов.
2. Опциональное поле включается ⇔ его чекбокс включён. В .md дополнительно требуется непустое
   значение (иначе секцию не пишем). В Excel выбранная колонка присутствует всегда, ячейки
   пустых значений — пустые.
3. Выбор данных применяется одинаково к xlsx, zip, tar.gz.
4. **Сценарии (`#### Scenario:`)** нет в списке чекбоксов. Предложение PO по умолчанию:
   сценарии — часть содержательного описания требования, привязать к чекбоксу **«Описание»**
   (выбрано «Описание» → в .md идут и тело, и сценарии). В Excel сценарии не выводим (лист
   табличный; сценарии остаются только в OpenSpec-архиве). — **на подтверждение при валидации.**

## 5. Бриф для дизайнера (что нарисовать)

Экран **«Формат выгрузки»** (`ExportModal`, шаг `format`). Добавить над карточками форматов блок
выбора данных из 2 именованных групп (визуальный язык согласовать с именованными группами
фильтров из Task 1 — те же заголовки `text-xs uppercase text-3`, дизайн-токены `var(--color-*)`):

1. Группа **«Обязательные данные»**: 3 чекбокса (Название, Критичность, Статус реализации) —
   состояние `checked + disabled`, визуально «залочено» (иконка замка / приглушённый цвет),
   тултип «Всегда включается в выгрузку».
2. Группа **«Дополнительные данные»**: 4 переключаемых чекбокса (Источник требования, Описание,
   Справочная информация, Связи). Дефолт — все включены (обратная совместимость с текущим полным
   экспортом). — на подтверждение.
3. Сохранить: 3 карточки форматов (Excel/.zip/.tar.gz), счётчик «Выбрано N требований», кнопки
   «← Назад» / «Отменить».
4. **Превью-подсказка**: короткий блок, который по текущему выбору перечисляет, что войдёт:
   «Колонки Excel: … / Секции OpenSpec: …». Плюс — мини-примеры содержания (см. ниже).

Состояния для отрисовки: залоченный чекбокс (disabled+checked), опциональный вкл/выкл, hover,
light/dark. Пустой крайний случай (сняты все опциональные) — как выглядит подсказка.

**Примеры содержания файлов, которые нужно показать на макете** (снимки, статичные):

- OpenSpec `.md`: (A) полный файл требования; (B) минимум (заголовок + 3 обязательные метки).

Формат сдачи (по /design): HTML+Tailwind макет экрана + галерея состояний + снимки примеров
