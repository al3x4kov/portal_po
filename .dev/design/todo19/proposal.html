Модалка требования: новая вкладка «Приоритизация»

Модалка разгружается на вкладки (это же закрывает замечание UX-ревью о перегрузе). Всё новое — на одной вкладке «Приоритизация». У требования может быть несколько источников. Поле «Источник» — с поиском по уже заведённым источникам проекта (см. второй источник — выпадающий список совпадений). У каждого источника свой приоритет (справочник проекта, названия без кодов), своя RICE-оценка и свой желаемый срок (квартал+год и/или конкретная дата). Итог — агрегат, а план реализации выставляет PO в отдельном блоке, глядя на пожелания источников.

Что добавляется в атрибуты требования

Источники — список, 0..N на требование новое

Вместо свободной строки source — список sources[], каждый элемент:

  • type: клиент/сделка · стейкхолдер · внутренний стандарт · другое
  • name: имя (справочник имён проекта собирается автоматически)
  • priority: значение из конфигурируемого справочника приоритетов (в UI — только название, без кодов)
  • rice: своя оценка этого источника (опционально)
  • targetQuarter/targetYear, targetDate: желаемый срок источника (опционально)
  • Миграция: текущее source («АС21», «ПАО») → sources[0].name

Итог требования — агрегаты: приоритет = старший по справочнику, RICE = max score. План реализации (квартал/год) + новая releaseDate — решение PO, не агрегат.

Приоритет источника новое

Значения — из справочника проекта (порядок = старшинство). Поставка содержит один дефолтный вариант:

Квартальная цель  по умолчанию

Остальное пользователь заводит сам (название + цвет) — с формы («Добавить свой вариант…») или в меню «Справочники». Пример настроенного справочника:

Критично для сделки Квартальная цель Демо совету директоров

Цвет несёт срочность, кодов вроде «S0» пользователь не видит.
