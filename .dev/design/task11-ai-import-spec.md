# Task 11 Дизайн-спек: «AI подгрузка ФТ/НФТ из документации» (Senior PO)

Источник: `.dev/todo/todo_10.md` (Постановка п.1–3). Методология извлечения — скилл портала
`apps/web/public/skills/project-po-extract.skill.md` (golden rule «никакого домысливания»,
провенанс на каждое требование, идемпотентность). Инфраструктура AI Hub — task 8
(ключ/baseURL глобально, модель per-project, OpenAI-совместимый клиент, инжектируемый
`AiClientFactory`); паттерн выбора модели — как в виджете чата (task 9).

## 0. Обзор

На главном экране проекта (управление ФТ/НФТ) в нижнем футере, справа от кнопок
«+ Функция» и «+ НФТ», появляется кнопка **«AI подгрузка из документации»**. Она открывает
модальное окно, где пользователь загружает архив документации (zip / tar.gz), выбирает
модель и запускает серверную автоматизацию: распаковка → пошаговое извлечение ФТ/НФТ через
AI Hub (много последовательных вызовов, т.к. контекстное окно модели маленькое —
ориентир Qwen-Coder-Next) → агрегация → наполнение ТЕКУЩЕГО проекта без перезаписи
существующих требований → уведомление об успехе.

## 1. UI (по постановке)

### 1.1 Кнопка
- В футере Main (`main-footer`), справа от `footer-add-function`/`footer-add-nfr`:
  «AI подгрузка из документации», вторичный стиль с AI-акцентом (иконка-искра).

### 1.2 Модальное окно (средний размер, ~640px)
- Заголовок: **«AI подгрузка ФТ и НФТ из документации»**.
- Сразу под заголовком: зона загрузки архива **zip / tar.gz** с локального устройства
  (input file + drag&drop; показать имя и размер выбранного файла, возможность заменить).
- **Выбор модели** — как в виджете чата: текущая модель проекта по умолчанию; список из
  `GET /api/ai/models`; если конфигурация не задана (нет ключа) — серый disabled с тултипом
  «Задайте API-ключ на экране AI (меню проекта → AI)» (используется ключ из меню AI, task 8).
- Кнопка **«Запустить анализ»**: активна только когда выбран файл (и определена модель);
  иначе disabled с тултипом «Загрузите архив документации» (или «Настройте AI Hub»).
- После запуска: кнопка запуска заменяется кнопкой **«Остановить»** (прекращение автоматизации).
- Ниже после запуска: **progress bar в %** и под ним **лог работы** автоматизации
  (моноширинный, автопрокрутка, строки с временем и уровнем info/warn/error).
- **X** в правом верхнем углу и **клик вне окна**: если автоматизация запущена — предупреждение
  (ConfirmDialog: «Прекратить автоматизацию?» — процесс будет остановлен); иначе — закрыть без
  вопросов. Подтверждение = отменить job + закрыть.
- **Успех**: уведомление в модалке (сколько ФТ/НФТ создано, сколько пропущено как существующие)
  + кнопка «Закрыть и перейти к проекту» (закрывает модалку; дерево требований уже обновлено).
- **Ошибка любого этапа**: в модалке блок ошибки — этап, читабельное сообщение и **инструкция
  что делать дальше** (см. §4); лог сохраняется; можно исправить и запустить заново.

## 2. Серверная автоматизация (этапы)

Долгоживущая работа — **job** на сервере, фронт поллит статус.

1. **unpack** — загрузка архива (multipart, как в import проекта), распаковка во временную
   директорию ОС (защита от path traversal / zip-slip — как NFR-5), поиск файлов документации
   `.md`/`.markdown`/`.txt`. Нет таких файлов → ошибка этапа.
2. **analyze** — для каждого файла: нарезка на чанки (константа ~12k символов, чтобы уложиться
   в маленькое контекстное окно) и **последовательные** вызовы chat.completions AI Hub, пока не
   обработана вся документация. Промпт кодирует правила скилла: строго из текста чанка, ничего
   не домысливать, каждый пункт с «источником» (файл + раздел), ответ — строгий JSON-массив
   `{type, name, description, source, criticality?, implemented?, targetQuarter?, targetYear?,
   parentName?}`. Невалидный JSON одного чанка → warn в лог и продолжить (не валить весь job);
   если ВСЕ чанки не распарсились → ошибка этапа.
3. **aggregate** — слить результаты: дедупликация по (тип, имя), иерархия только когда родитель
   присутствует в извлечённом наборе или среди существующих требований проекта.
4. **populate** — наполнение проекта через существующие сервисы требований/связей:
   - существующие ФТ/НФТ **не перезаписываем**: совпадение имени в рамках типа → пропуск
     (skipped, warn в лог);
   - провенанс пишем в поле **source** требования (файл§раздел из извлечения);
   - связи CHILD_OF после создания; доменные ошибки связи (цикл, второй родитель) → warn в лог,
     требование остаётся без связи.
5. **done** — уведомление об успехе + итоги (created/skipped по типам, связи).

**Отмена** («Остановить», подтверждение на X/оверлей): job переводится в `cancelled` на границе
ближайшего AI-вызова; уже созданные к этому моменту требования остаются (лог фиксирует, сколько
успело создаться).

**Прогресс (%):** unpack 0–5, analyze 5–80 (по обработанным чанкам), aggregate 80–85,
populate 85–100 (по созданным требованиям).

## 3. Решения PO (гейт — закрыто)

1. **Пробелы источника** (скилл требует подтверждения у пользователя, автоматизация спросить
   не может): критичность не указана → `MEDIUM`; статус не указан → `implemented=false` c
   target = следующий квартал от текущей даты; в лог — warn о применённых умолчаниях,
   в описание требования умолчания НЕ пишем (описание — только пересказ источника).
2. **Провенанс** — обязательный `source` из модели ответа AI; пишется в поле «Источник»
   требования (оно уже есть в портале, FR-19). Требование без source отбрасывается (warn).
3. **Job в памяти сервера** (локальное однопроцессное приложение): Map jobId→state,
   один активный job на проект (повторный запуск при running → 409). Поллинг фронта ~800 мс.
4. **Лимиты**: архив ≤ 50 МБ, файлов документации ≤ 500, чанк ≤ 12 000 символов — константы
   контракта в @po/core.
5. **Модель**: override из модалки → модель проекта → иначе кнопка запуска disabled (фронт) и
   400 (сервер). Температура 0.2 (экстракция, не генерация), max_tokens 2000 — константы core.
6. **«Перейти к проекту»**: модалка открыта на самом проекте, поэтому кнопка успеха закрывает
   модалку и инвалидирует запросы требований (дерево уже обновлено). Отдельной навигации нет.
7. Результат агрегации живёт внутри job (JSON в памяти) — «формат, удобный автоматизации»;
   на диск промежуточный MD не пишем.
8. Cancel не откатывает уже созданные требования (идемпотентность: повторный запуск того же
   архива пропустит созданное как существующее).

## 4. Ошибки этапов → сообщение + инструкция (обязательные тексты)

| Этап | Пример причины | Инструкция пользователю |
|---|---|---|
| upload/unpack | не zip/tar.gz, битый архив, лимит размера | «Проверьте формат архива (zip или tar.gz) и размер до 50 МБ, соберите архив заново и повторите» |
| unpack | нет .md/.txt файлов | «В архиве нет файлов документации (.md/.txt). Добавьте документацию в архив и повторите» |
| analyze | нет ключа / модель не задана | «Настройте AI Hub: задайте API-ключ на экране AI и выберите модель» |
| analyze | AI Hub недоступен / 401 / лимит | «Проверьте доступность AI Hub, корректность API-ключа и повторите анализ» |
| analyze | все ответы не распарсились | «Модель вернула неструктурированный ответ. Попробуйте другую модель или повторите» |
| populate | доменные ошибки | «Часть элементов не создана (см. лог). Исправьте данные в проекте и повторите — существующие не будут задублированы» |

## 5. Матрица сценариев (для QA)

1. Кнопка видна в футере Main справа от «+ Функция»/«+ НФТ»; открывает модалку.
2. Без файла «Запустить анализ» disabled + тултип; после выбора файла — активна.
3. Без ключа — селект модели серый + тултип, запуск disabled.
4. Happy-path (AI-стаб): zip с md → прогресс до 100%, лог этапов, итог created>0; дерево
   требований пополнилось; провенанс в поле «Источник».
5. Существующие не перезаписаны: повторный запуск того же архива → created=0, skipped>0,
   существующие требования не изменены.
6. Отмена: «Остановить» → статус cancelled, лог фиксирует остановку; модалку можно закрыть без
   подтверждения.
7. X/клик-вне при running → ConfirmDialog; подтверждение отменяет job и закрывает; отказ —
   автоматизация продолжается. При idle — закрытие без вопросов.
8. Ошибка этапа (стаб отдаёт 500 / архив без md) → блок ошибки с инструкцией, job failed.
9. tar.gz работает так же, как zip.

## 6. Вне скоупа

Параллельная обработка чанков; стриминг лога (поллинг достаточен); откат созданного при отмене;
обработка PDF/Word внутри архива (только .md/.markdown/.txt); несколько одновременных job на
один проект; сохранение MD-отчёта на диск.
