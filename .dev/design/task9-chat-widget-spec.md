# Task 9 Дизайн-спек: плавающий виджет AI-чата (Senior PO)

Источник: `.dev/todo/todo_9.md` (Постановка п.1–2). Опирается на инфраструктуру AI Hub из
task 8 (`.dev/design/task8-ai-feature-spec.md`): API-ключ/baseURL — глобальный конфиг,
модель — per-project, клиент OpenAI-совместимый. Ничего не домысливаем сверх постановки;
открытые вопросы закрыты решениями PO в §6.

## 0. Обзор

Один новый UI-объект — **виджет чата**, доступный на ВСЕХ экранах приложения
(Start, NewProject, Import, OpenExisting, Main, Dashboard, AiPage). Два состояния:

1. **Свёрнут (по умолчанию):** небольшая круглая иконка сообщения (FAB), перетаскиваемая
   по экрану. Клик (без перетаскивания) → иконка исчезает, открывается виджет.
2. **Развёрнут:** карточка чата, тоже перетаскиваемая (за верхнюю панель). Крестик «X»
   сворачивает обратно в иконку, переписка НЕ удаляется.

## 1. Поведение (по постановке)

### 1.1 Иконка (FAB)
- Небольшая (~48px) круглая кнопка с иконкой сообщения, поверх контента (fixed, высокий z-index),
  дефолтная позиция — правый нижний угол.
- Перетаскивается мышью в любое место экрана; позиция ограничена видимой областью.
- Клик = открыть виджет (иконка скрывается). Различать drag и click порогом смещения (~5px).

### 1.2 Виджет — верхняя панель
- **Дропдаун переопределения модели:** показывает текущую выбранную модель.
  - Источник списка — `GET /api/ai/models` (доступен при сохранённом API-ключе).
  - Дефолт: модель проекта из `GET /api/ai/config?projectId=…`, если открыт проект и модель задана.
  - Если конфигурация не задана (нет ключа) — дропдаун **серый/disabled**, вместо модели
    приглушённый текст, по наведению **тултип с подсказкой как настроить**: «Задайте API-ключ
    в меню AI (экран проекта → AI)». Используется тот же ключ, что задан в меню AI (task 8).
  - Выбор в дропдауне — локальное переопределение для чата; в конфиг проекта НЕ пишется.
- **Кнопка «Новый чат»:** затирает переписку (история очищается, поле ввода очищается).
- **Иконка «X» справа сверху:** закрывает видимость виджета (остаётся только FAB),
  переписка сохраняется и доступна при повторном открытии.
- За верхнюю панель виджет перетаскивается по экрану.

### 1.3 Виджет — середина (основная часть)
- Лента переписки: вмещает 5–6 сообщений и минимум 500 символов контента без прокрутки
  (при большем объёме — вертикальный скролл, автопрокрутка к последнему сообщению).
- У каждого сообщения аватар-иконка: **бот** (робот/искра) у ответов ассистента слева,
  **юзер** у сообщений пользователя справа — чтобы было видно, кто пишет.
- Состояния: пустой чат — приглашение («Спросите ассистента…»); ожидание ответа — индикатор
  «печатает…»; ошибка — читабельное сообщение в ленте (без API-ключа в тексте).

### 1.4 Виджет — низ
- Поле ввода сообщения (textarea 1–3 строки, Enter = отправить, Shift+Enter = перенос)
  и кнопка «Отправить».
- Кнопка/отправка disabled, пока: пусто; идёт запрос; не настроен ключ или не определена модель
  (в этом случае подсказка-тултип как в 1.2).

## 2. Контракт (черновик для архитектора; финализирует backend)

Единый контракт в `@po/core` (`packages/core/src/validation/ai.ts`), рядом со схемами task 8:

- `POST /api/ai/chat`
  - Request: `{ projectId?: string, model?: string, messages: Array<{role:'user'|'assistant', content:string}> }`
    (история — последние N сообщений, лимиты в схеме).
  - Модель на сервере: `model` из запроса → иначе `modelByProject[projectId]` → иначе 400.
  - Нет ключа → 400 «AI Hub API key is not configured». Upstream-ошибка → 502 (санитизация ключа).
  - Response: `{ message: { role: 'assistant', content: string } }`.
- Системный промпт (RU): ассистент Product Owner в портале управления требованиями; отвечает
  кратко и по делу, на русском.

## 3. Бриф дизайнеру

- Макет в `design-out/task9/` (HTML + Tailwind, светлая/тёмная темы по токенам портала
  `design-out/tokens.css`): два состояния — FAB и открытый виджет.
- Виджет: ширина ~380px, высота ~560px (лента ~5–6 сообщений, ≥500 символов видимого текста);
  скругления/тени/цвета — как модалки портала.
- Верхняя панель: [дропдаун модели][Новый чат][X]; серое состояние дропдауна + тултип.
- Сообщения: пузыри, иконка бота слева / юзера справа, разные фоны для ролей.
- Низ: textarea + primary-кнопка «Отправить».

## 4. Матрица сценариев (для QA)

1. FAB виден на каждом экране; drag FAB меняет позицию; click открывает виджет (FAB скрыт).
2. X закрывает виджет → FAB снова виден; переписка сохранена при повторном открытии.
3. «Новый чат» очищает ленту.
4. Без настроенного ключа: дропдаун серый, тултип с подсказкой, отправка disabled.
5. С ключом (AI-стаб e2e): отправка сообщения → ответ ассистента в ленте с иконкой бота.
6. Переопределение модели в дропдауне используется в запросе (стаб фиксирует model).
7. Ошибка апстрима → читабельное сообщение об ошибке в ленте, переписка не теряется.

## 5. Вне скоупа

- Персистентность переписки на диск/сервер; стриминг ответов; markdown-рендеринг ответов;
  вложения; изменение конфига AI из виджета.

## 6. Решения PO (гейт после дизайна — закрыто)

1. **Переписка живёт в памяти клиента** (Zustand store), переживает навигацию между экранами;
   перезагрузка страницы очищает. X не очищает, «Новый чат» очищает.
2. **projectId необязателен:** на экранах без открытого проекта чат работает при явно выбранной
   в дропдауне модели; если модель не определить (нет проекта и нет override) — отправка
   disabled с подсказкой.
3. **Override модели** — состояние виджета, не персистится в конфиг.
4. **История в запросе** — последние 20 сообщений (константа backend).
5. **Параметры чата:** `temperature = 0.7`, `max_tokens = 1000` — константы в `@po/core`
   (`AI_CHAT_TEMPERATURE`, `AI_CHAT_MAX_TOKENS`), не в UI.
6. **Позиция FAB/виджета** не персистится (сбрасывается при перезагрузке).
7. Монтирование — глобально в `App.tsx` (над Routes), чтобы виджет был на всех экранах.
8. Иконки бота/юзера — inline SVG в стиле портала (без новых зависимостей).
