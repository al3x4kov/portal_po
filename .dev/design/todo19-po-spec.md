## E-A. Множественные источники требования

**Контракт (владелец — backend, @po/core):** у требования — массив `sources: SourceEntry[]` (0..N). Прежнее поле `source?: string` устаревает; при чтении старых `.md` мигрируется в `sources[0]` (тип `TEXT`, имя = прежняя строка). Round-trip markdown остаётся lossless.

```
SourceEntry {
  type: 'CLIENT' | 'STAKEHOLDER' | 'STANDARD' | 'TEXT'
  name: string                 // 1..100, ссылается на справочник источников проекта (по имени)
  priorityId: string           // код из справочника приоритетов проекта
  rice?: { reach, impact, confidence, effort }   // см. E-B
  targetQuarter?: 'Q1'..'Q4'
  targetYear?: number           // 2020..2100
  targetDate?: string           // ISO yyyy-mm-dd, опционально
}
```

### ФТ
- **ФТ-A1 (CRITICAL)** — Требование хранит список источников (0..N). Порядок сохраняется; первый/старший показывается свёрнуто в дереве.
- **ФТ-A2 (CRITICAL)** — В модалке требования на вкладке «Приоритизация» — список карточек источников с кнопками «Добавить источник» и «Убрать».
- **ФТ-A3 (HIGH)** — Поле «Источник» — combobox с поиском/подстановкой по справочнику источников проекта; при вводе показываются совпадения + пункт «Создать новый источник» (создаёт запись в справочнике).
- **ФТ-A4 (HIGH)** — Миграция: существующее строковое `source` при первом чтении/сохранении становится `sources[0]` типа TEXT; данные не теряются.

### Критерии приёмки (A2/A3)
- GIVEN открыта вкладка «Приоритизация», WHEN нажата «Добавить источник», THEN появляется пустая карточка источника (тип, имя, приоритет, срок, RICE).
- GIVEN в поле «Источник» введены ≥1 символ, WHEN есть совпадения в справочнике проекта, THEN они показываются списком с подсветкой введённого; выбор подставляет имя.
- GIVEN совпадений нет, THEN доступен пункт «Создать новый источник «<ввод>»»; выбор добавляет имя в справочник и в карточку.
- GIVEN у требования 2 источника, WHEN сохранено и переоткрыто, THEN оба источника с их полями на месте (lossless).

## E-B. RICE-скоринг на источник + агрегаты

Базовые шкалы-селекты (решение PO): Reach 1..5; Impact 0.25/0.5/1/2/3; Confidence 0.5/0.8/1; Effort 0.5/1/2/3/5/8. `score = Reach × Impact × Confidence / Effort`, округление до 0.1.

### ФТ
- **ФТ-B1 (HIGH)** — Каждый источник имеет опциональный RICE (4 селекта); score считается на лету и показывается в карточке источника.
- **ФТ-B2 (HIGH)** — Итоговый RICE требования = **max** score по источникам; показывается в модалке (строка «Итог») и в колонке «RICE» дерева.
- **ФТ-B3 (MEDIUM)** — Колонка «RICE» в дереве сортируется (убыв./возр.); требования без оценки идут в конец.
- **ФТ-B4 (LOW)** — Дашборд: топ-5 требований по итоговому RICE.

### Критерии приёмки
- GIVEN источник с Reach=4, Impact=3, Confidence=0.8, Effort=3, THEN score = 3.2.
- GIVEN два источника со score 3.2 и 2.4, THEN итог требования = 3.2.
- GIVEN RICE ни у одного источника не заполнен, THEN итог = «—», в сортировке требование в конце.
- Вычисление — в `@po/core` (переиспользуется сервером и вебом), покрыто unit-тестами.

## E-C. Справочники проекта (новый пункт меню)

Новый экран `/p/:id/dictionaries` — «Справочники». Хранение — на уровне проекта (файл конфигурации проекта; формат — решение backend-агента, round-trip). Пункт в навигации проекта рядом с «Дерево / Дашборд / AI».

### C1. Справочник приоритетов источников
Элемент: `{ id, name (1..40), color (из палитры токенов), order }`. Порядок = старшинство (сверху — старший), влияет на агрегат приоритета требования. **Поставка: один дефолт «Квартальная цель».**

- **ФТ-C1.1 (CRITICAL)** — CRUD приоритетов: добавить (название + цвет), переименовать, изменить цвет, удалить, переупорядочить (drag/стрелки).
- **ФТ-C1.2 (HIGH)** — Быстрое добавление с формы требования: пункт «Добавить свой вариант…» открывает инлайн-ввод (название + палитра); новый приоритет попадает в справочник и сразу доступен.
- **ФТ-C1.3 (HIGH)** — В UI приоритет отображается **только названием + цветом** (никаких кодов «S0»). Цвет — из выбранного в справочнике.
- **ФТ-C1.4 (MEDIUM)** — Удаление используемого приоритета: предупредить и предложить перенос затронутых источников на другой приоритет (не оставлять «висячий» priorityId).

### C2. Справочник источников
Элемент: `{ id, name (1..100), type: CLIENT|STAKEHOLDER|STANDARD|TEXT, color? }`.

- **ФТ-C2.1 (HIGH)** — CRUD источников; наполняется вручную и **автосбором** имён, введённых в требованиях.
- **ФТ-C2.2 (MEDIUM)** — «АС21», «ПАО» и прочие прежние строковые значения мигрируют сюда как тип TEXT.
- **ФТ-C2.3 (LOW)** — Переименование источника в справочнике отражается в требованиях, где он использован (связь по имени/id).

### Критерии приёмки
- GIVEN новый проект, THEN справочник приоритетов содержит ровно один элемент «Квартальная цель».
- GIVEN в справочнике приоритет с цветом красный «Критично для сделки», WHEN он выбран у источника, THEN в дереве бейдж источника красный с этим названием.
- GIVEN приоритет используется в N источниках, WHEN его удаляют, THEN система требует выбрать замену либо запрещает удаление с пояснением.
- GIVEN имя источника впервые введено в требовании, THEN оно появляется в справочнике источников (автосбор).

## E-D. Сроки: пожелания источников + решение PO

### ФТ
- **ФТ-D1 (HIGH)** — У каждого источника опционально: `targetQuarter`+`targetYear` и/или `targetDate` (дата без времени). Всё опционально.
- **ФТ-D2 (HIGH)** — Блок «Решение PO — план реализации»: существующие поля требования `targetQuarter`/`targetYear` + новое опциональное `releaseDate`. Над полями — сводка пожеланий всех источников (имя → срок), чтобы PO решал «глядя на список».
- **ФТ-D3 (MEDIUM)** — Валидация согласованности: если дата (у источника или releaseDate) вне выбранного квартала/года — **бледная подсветка-предупреждение** (янтарная рамка + примечание), НЕ блокирует сохранение.
- **ФТ-D4 (MEDIUM)** — Колонка дерева «Срок реализации» — двухуровневая: сверху квартал/год (план PO), под ним дата выпуска только если задана; «Реализовано» для готовых.

### Критерии приёмки
- GIVEN implemented=false, THEN targetQuarter+targetYear требования обязательны (как сейчас); releaseDate опционально.
- GIVEN releaseDate = 2026-11-05 и квартал требования = Q3 2026, THEN поле подсвечено янтарным с примечанием «дата вне 3 квартала»; сохранение проходит.
- GIVEN у источника targetDate = 2026-09-15 и квартал Q3 2026, THEN предупреждения нет (сентябрь в Q3).
- GIVEN releaseDate задан, THEN в дереве показывается «<квартал> / выпуск <дата>».

## E-E. Look-n-feel (полный проход по norman-review.md)

Независимый трек (только apps/web, без контрактов). Объём — разумная первая волна по ревью Нормана. Кандидаты (детализируем на дизайне трека A):

- **ФТ-E1 (HIGH)** — Действия строки дерева видимы всегда (не opacity-0 до hover); доступны с клавиатуры/тача.
- **ФТ-E2 (HIGH)** — Шапка главного экрана: имя проекта крупно и первым, путь — вторичной строкой.
- **ФТ-E3 (HIGH)** — Модалка требования на вкладках (Основное / Приоритизация / Описание и сценарии / Связи / Справочно); убрать confirm на обычном сохранении.
- **ФТ-E4 (MEDIUM)** — 100% Lucide-иконки вместо эмодзи/символов (Start-карточки, дерево).
- **ФТ-E5 (MEDIUM)** — Иконки «добавить ФТ»/«добавить НФТ» различать формой (Plus/ShieldPlus), не только цветом.
- **ФТ-E6 (MEDIUM)** — Развести Toast-уведомления и FAB чата по разным углам.
- **ФТ-E7 (MEDIUM)** — Дропзона импорта: подсветка dragover, автоимя из имени файла, прогресс.
- **ФТ-E8 (LOW)** — Start: список недавних проектов; читаемость чипов связей (>10px); объяснения дизейбла везде текстом.

## НФТ (применимые к доработкам)

- **НФТ-1 (Производительность, HIGH)** — Пересчёт RICE и агрегатов — мгновенный (клиентский, без запроса к серверу); дерево с новыми колонками не деградирует на текущих объёмах.
- **НФТ-2 (Совместимость данных, CRITICAL)** — Обратная совместимость `.md`: старые требования без `sources` читаются, мигрируются без потерь; round-trip lossless (существующее требование `@po/core`).
- **НФТ-3 (Единый контракт, HIGH)** — Типы и валидация `sources`, RICE, справочников — только в `@po/core` (Zod), переиспользуются сервером и вебом; без дублирования правил.
- **НФТ-4 (Целостность, HIGH)** — Нет «висячих» ссылок: priorityId источника всегда указывает на существующий приоритет; удаление приоритета/источника обрабатывает затронутые требования.
- **НФТ-5 (Доступность, MEDIUM)** — Цвет приоритета не единственный носитель смысла: всегда рядом текстовое название; контраст бейджей ≥ AA.
- **НФТ-6 (Тестопригодность, HIGH)** — data-testid на новых элементах (карточка источника, combobox, справочники, поля сроков) для e2e; ядро покрыто unit ≥90%.
- **НФТ-7 (UX-консистентность, MEDIUM)** — Новые экраны/поля используют дизайн-токены проекта (палитра, радиусы, типографика); тёмная тема поддержана.

## Детали Гейта 2 — ЗАКРЫТЫ решением PO
1. **Палитра цветов приоритетов** — фиксированный набор из дизайн-токенов (8–10 цветов), не свободный HEX.
2. **Автосбор источников** — добавлять имя в справочник **сразу при вводе** (не откладывать до сохранения требования).
3. **releaseDate при implemented=true** — **прятать** (единообразно с targetQuarter/targetYear).
4. **Look-n-feel** — делаем **всё сразу** (E1–E8 в одной волне трека E), не поэтапно.
