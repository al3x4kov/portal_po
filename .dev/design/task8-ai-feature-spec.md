# Task 8 — Дизайн-спек: интеграция с AI Hub (Senior PO)

Источник: `.dev/todo/todo_8.md` (п.1–3). Решения пользователя закреплены ниже. Ничего не
домысливаем сверх постановки.

## 0. Обзор
Две связанные части, одна общая инфраструктура (клиент AI Hub + конфиг):
- **A. Экран «AI»** — новый пункт меню (виден для любого открытого проекта) → страница из 2 панелей:
  ввод настроек подключения (слева) + пошаговая инструкция (справа).
- **B. Кнопка «AI Hub generation»** на поле «Описание» формы требования → запрос в AI Hub →
  превью → «Отменить»/«Применить» (append в конец описания с новой строки).

AI Hub **OpenAI-совместим**: `baseURL` по умолчанию `https://api.ai.sbt/openai/v1`,
`client.models.list()`, `client.chat.completions.create({ model, messages })`, пример модели
`GigaChat-2-Pro`. Внешний AI Hub из среды разработки недоступен → тесты на моках `openai`.

## 1. Решения пользователя (закреплено)
1. **Хранение конфига — гибрид:** `apiKey` + `baseURL` — глобально (персональный набор на
   пользователя); выбранная **модель** — per-project.
2. **API-ключ:** плейнтекст в локальном конфиг-файле (в `.gitignore`), в UI маскируется
   (`••••`, кнопка показать/скрыть), никогда не логируется, наружу (в GET) в открытом виде не отдаётся.
3. **Генерация описания:** контекст требования (имя, тип, критичность, текущее описание, имя/
   описание проекта) + **опциональная** подсказка пользователя.

## 2. Хранение конфига (важно для архитектора)
Один **глобальный** JSON-файл, напр. `<PROJECTS_ROOT>/.ai-config.json` (точный путь — за
архитектором), структура:
```json
{
  "baseURL": "https://api.ai.sbt/openai/v1",
  "apiKey": "<plaintext>",
  "modelByProject": { "<projectId>": "GigaChat-2-Pro" }
}
```
- **Почему модель хранится в глобальном файле под `modelByProject`, а НЕ внутри
  `Projects/<id>/`:** архивный экспорт пакует всю папку проекта (`ArchiveRepo.export` →
  `addLocalFolder(projectDir)`), поэтому любой файл внутри `Projects/<id>/` попал бы в выгрузку.
  Держим per-project-модель в глобальном конфиге по ключу projectId — «per-project» по смыслу,
  но без утечки в архивы.
- Файл добавить в `.gitignore`. Права/логи: ключ не логировать; при ошибках — без значения ключа.
- Автоподтягивание: экран AI и кнопка генерации читают конфиг автоматически, если он есть.

## 3. Экран «AI» (2 панели)
Маршрут `/p/:id/ai`; пункт меню в `Sidebar` (иконка, tooltip «AI»), `activePage` расширяется на `'ai'`.
Страница-аналог по верстке — `Dashboard`.

**Левая панель «Подключение к AI Hub»:**
- **API-ключ** — поле `password` с маскировкой + кнопка показать/скрыть. Если ключ уже сохранён —
  показывать «ключ сохранён» и маску; повторный ввод перезаписывает. Пустое поле при сохранении
  без ввода — ключ не трогаем.
- **Base URL** — текстовое поле, дефолт `https://api.ai.sbt/openai/v1`, валидируется как URL.
- **Кнопка «Сохранить и загрузить модели»** → сохранить конфиг (PUT) → запросить список моделей (GET).
- **Модель** — выпадающий список (из ответа `models.list`); сохраняется per-project. **Fallback:**
  если список не загрузился (нет ключа/сеть) — разрешить ручной ввод `model id` текстом.
- **Статус подключения** — успех («загружено N моделей») / ошибка (читабельный текст без ключа).
- Пустое состояние: ключ не задан → подсказка «Введите API-ключ, чтобы загрузить модели».

**Правая панель «Инструкция»** — нумерованные шаги (дословно из постановки):
1. Авторизация в AIHub: открыть `https://hub.ai.sbt/` (ссылка в новой вкладке, `rel="noopener"`),
   «Войти» справа вверху, вход под персональной учётной записью.
2. Получение API-ключа: раздел «API-ключи» → «Создать новый ключ» → выбрать тип ключа →
   название (напр. «test») → «Создать ключ» → скопировать и сохранить в надёжном месте.
3. Base URL: `https://api.ai.sbt/openai/v1`.
4. Список моделей: получить перед работой (в портале — выпадающий список).
5. Первый запрос: AIHub совместим с OpenAI API — достаточно сменить `base_url`.
- Опционально блок-справка с примером кода Node.js (`openai` SDK) — свернутый, только для чтения.

## 4. Кнопка «AI Hub generation» (форма требования)
Место: `RequirementModal`, рядом с полем «Описание».
**Поток:**
1. Клик по кнопке → раскрывается панель/модалка: необязательное поле «Уточняющая подсказка»
   (textarea) + кнопка «Сгенерировать».
2. Загрузка (спиннер, кнопки заблокированы).
3. Превью: возвращённое описание (read-only) + кнопки **«Отменить»** / **«Применить»**
   (+ «Сгенерировать заново»).
4. **Применить** = добавить сгенерированный текст в КОНЕЦ текущего описания с новой строки
   (`current ? current + '\n' + generated : generated`), не затирая введённое.
**Предусловия:** нужен сохранённый `apiKey` + выбранная модель для текущего проекта. Если нет —
кнопка ведёт/подсказывает перейти на экран «AI» (дизраблить с тултипом либо мягкий редирект).
**Ошибки AI Hub** (401/сеть/лимит/пустой ответ) — показать читабельное сообщение, описание не менять.

## 5. Структура запроса к AI Hub (дизайн промпта — по ресёрчу)
`chat.completions.create({ model: <per-project>, messages, temperature≈0.4, max_tokens≈700 })`.
**System (RU):** роль — ассистент по инженерии требований; задача — сформировать КАЧЕСТВЕННОЕ
описание требования для портала управления требованиями. Явные критерии качества:
**недвусмысленность, понятность, корректность, проверяемость**. Стиль: конкретно и проверяемо,
без «воды», 1–3 предложения или короткое структурированное описание. НЕ выдумывать факты сверх
предоставленного контекста; при необходимости допущений — помечать «Допущение: …». Вернуть ТОЛЬКО
текст описания (без преамбул, markdown-заголовков, кавычек). Язык — русский. Длина в пределах домена (≤5000).
**User:** структурированный контекст:
- Проект: `<name>` (+ описание проекта, если есть).
- Требование: тип (ФТ/НФТ), имя, критичность; текущее описание (если есть → «улучшить/дополнить»,
  иначе → «сформировать с нуля»).
- Опциональная подсказка пользователя (если введена).
- (few-shot) один короткий пример хорошего описания в стиле портала — для задания стиля.
**Практики (ресёрч):** few-shot + контекст + явные критерии качества > zero-shot/«одна строка»;
структурированный промпт; human-in-the-loop = превью+применить. Одношаговый запрос (без стриминга)
для простоты и тестируемости.

## 6. Контракт для архитектора (черновик; финализировать в @po/core Zod)
- `GET  /api/ai/config?projectId=<id>` → `{ baseURL, hasApiKey: boolean, model?: string }`
  (**ключ наружу не отдаём**; только `hasApiKey` + маска при необходимости).
- `PUT  /api/ai/config` body `{ baseURL?, apiKey?, projectId?, model? }` → сохранить (ключ
  обновляется только если передан непустым; модель — под `modelByProject[projectId]`).
- `GET  /api/ai/models` → `{ models: string[] }` (использует сохранённые key+baseURL; ошибки → 4xx с текстом).
- `POST /api/ai/generate-description` body
  `{ projectId, requirement: { name, type, criticality, description? }, projectName?, projectDescription?, userHint? }`
  → `{ description: string }`. Сервер строит system+user (см. §5), берёт per-project модель.
- Зависимость `openai` на сервере; клиент инкапсулирован в сервис (инъекция для моков в тестах).
- Схемы конфига/запросов — в `@po/core` (Zod), переиспользуются server + web.

спеку. Открытые вопросы закрыты:

2. few-shot — включаем **один короткий** пример хорошего описания в промпт (в стиле портала).
3. Стартовые параметры генерации: **`temperature = 0.4`, `max_tokens = 700`** — вынести в константы
   backend (не в UI).
4. «Уточняющая подсказка» — **inline-панель** рядом с полем «Описание» в форме требования (как в макете).
5. Кнопка генерации без конфига — **disabled + тултип-ссылка «Настройте AI Hub» → /p/:id/ai** (как в макете).
