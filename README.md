# project_po — Управление требованиями для Product Owner

Локальное приложение, в котором Product Owner описывает **функциональные (ФТ)** и
**нефункциональные (НФТ)** требования продукта, строит между ними древовидные связи и
хранит результат в **машиночитаемом Markdown** — чтобы требования можно было отдавать
ИИ-агентам как источник истины.

- **Без базы данных.** Источник истины — файлы на диске в каталоге `Projects/`.
- **Формат — OpenSpec.** Каждое требование — отдельный файл в OpenSpec-разметке
  (`### Requirement:` / `#### Scenario:`). Подробнее — `docs/architecture/ADR-001-openspec-storage.md`.
- **Локальный запуск.** Браузерный фронтенд + локальный Node-сервер, который выполняет
  все операции с файловой системой и раздаёт SPA. Один процесс — всё приложение.
- **Готово к ИИ.** REST для агентов + MCP-сервер (stdio) поверх той же доменной логики.

## Требования

- **Node.js ≥ 20** (CI использует 22) и npm.

## Быстрый старт

```bash
git clone <repo> project_po && cd project_po
npm install            # монорепо (npm workspaces): установит зависимости всех пакетов
npm run build          # сборка core + server + web (+ mcp)
node apps/server/dist/main.js
```

Откройте <http://127.0.0.1:3000> — сервер раздаёт SPA на `/` и API на `/api`.
Проекты сохраняются в `./Projects/` (создаётся автоматически).

### Переменные окружения (сервер)

| Переменная      | По умолчанию      | Назначение                                 |
| --------------- | ----------------- | ------------------------------------------ |
| `PORT`          | `3000`            | Порт HTTP                                  |
| `HOST`          | `127.0.0.1`       | Хост                                       |
| `PROJECTS_ROOT` | `<repo>/Projects` | Где хранятся проекты (каждый — подкаталог) |
| `LOG_LEVEL`     | `info`            | Уровень логов (pino)                       |

## Как пользоваться

1. **Стартовый экран:** «Новый проект» / «Импорт» / «Открыть существующий».
2. **Главный экран:** две секции — «Функциональные требования» и «Нефункциональные
   требования», каждая с кнопкой **+**. Требования показываются деревом (функции →
   подфункции без ограничения вложенности).
3. **Создание/редактирование** — в модальном окне: название (с автопроверкой
   уникальности), критичность, описание, «реализовано/не реализовано» (при «не
   реализовано» — квартал и год). Изменения **сохраняются сразу** в `.md`-файл.
4. **Связи:** `PARENT_OF/CHILD_OF` (иерархия), `RELATES_TO`, `DEPENDS_ON`, `BLOCKED_BY`.
   Проверяются циклы, единственность родителя, отсутствие висячих ссылок.
5. **Работа с деревом:** переключатель «Раскрыть все / Скрыть зависимости», поиск по
   названию (показывает и предков совпадения), мультиселект-фильтр по критичности,
   боковая панель для длинного описания.
6. **Экспорт:** архив `.zip` / `.tar.gz` (пригоден для повторного импорта) или книга
   **Excel `.xlsx`** (листы `Requirements` и `Links`; только выгрузка, не импортируется).

## Разработка

```bash
# Фронтенд в dev-режиме (Vite, проксирует /api → сервер; сервер запустите отдельно)
npm run dev -w @po/web

# Проверки (то же, что гоняет CI)
npm run format:check
npm run lint
npm run typecheck
npm test              # unit + component (Vitest) с порогом покрытия
npm run e2e           # E2E (Playwright): собирает и поднимает реальное приложение
```

- **Один тест:** `npx vitest run packages/core/src/md/markdown.test.ts` (фильтр по имени: `-t "…"`).
- **Один E2E-файл:** `npx playwright test e2e/tests/happy-path.spec.ts`.
- E2E запускается серийно против одноразового `PROJECTS_ROOT` во временной директории.

## MCP-сервер (для ИИ-агентов)

Поверх доменной логики доступен MCP-сервер (транспорт stdio):

```bash
npm run build
node apps/mcp/dist/main.js          # PROJECTS_ROOT переопределяется через env
```

Инструменты: `list_projects`, `get_project`, `list_requirements`, `get_requirement`,
`create_requirement`, `update_requirement`, `link_requirements`, `delete_requirement`,
`export_project`. Входы валидируются теми же Zod-схемами, что и REST.
Также доступен `GET /api/projects/:id/requirements?format=openspec` — склеенный OpenSpec-текст.

## Структура репозитория

```
packages/core   @po/core   — доменное ядро: типы, Zod, OpenSpec-сериализация, граф связей
apps/server     @po/server — Fastify API (routes → services → repositories → fs), раздаёт SPA
apps/web        @po/web    — React + Vite + TS + Tailwind (SPA)
apps/mcp        @po/mcp    — MCP-сервер (stdio) поверх сервисов
e2e                        — Playwright E2E
```

Слоистость строгая: `web → (HTTP) → server → core`. `packages/core` не знает про fs/http.
